Manual / Chapter 16

JavaScript API

The cleanrules package for JavaScript and TypeScript: conditions built with F and methods, rules and rule sets, decisions with native JavaScript values, structured explanations and summaries, documents, decision tables and errors. The same engine as every other language, in two builds with one API: a native addon for Node and a WebAssembly module for browsers, Deno and other runtimes.

Not on npm yet. npm i cleanrules does not work until the first release (task M.2); build the package from the repository (installation). This page is written from the package's type declarations (index.d.ts) and its README at commit 01ea4a4. Node 22.12 or later, Deno 2.6 or later, and browsers through the WebAssembly build.

A first program#

A rule read from the rule syntax with ruleFromText, one built in code, a decision, why a rule did not fire, the explanation and summary as text, and the rule set written back. Run as TypeScript with Node 26 on the native addon; the WebAssembly build prints the same.

api.tsJavaScript binding · runs
import { F, Rule, RuleSet, decimal, dumps, ruleFromText } from 'cleanrules'

const vip = ruleFromText('RULE vip PRIORITY 10 IF customer.years > 5 AND order.total > 1000 THEN discount = 0.15')
const loyal = new Rule('loyal', F.customer.years.gt(2), { discount: decimal('0.05') }, { priority: 5 })
const rules = new RuleSet([vip, loyal], { hitPolicy: 'priority' })

const decision = rules.evaluate({ customer: { years: 7 }, order: { total: 900 } })
console.log(decision.fired, decision.output)
console.log(decision.whyNot('vip').causes[0]?.counterfactual)
console.log(String(decision.explain()))
console.log(String(rules.summary()))
console.log(dumps(rules, { format: 'text' }))

Outputs come back as native values: decimal('0.05') is a Decimal, because JavaScript has no exact decimal. The explanation and the summary are the text every language prints. The worked examples have a TypeScript tab each.

Entry points and builds#

ImportWhat
cleanrulesThe idiomatic API on this page, the errors, the marker values, version and FORMAT_VERSION.
cleanrules/nativeThe native layer the API is built on: rule sets read from documents, outputs and explanations as JSON text (below).
cleanrules/wasmThe WebAssembly build, initialised by hand with await init(source) (below).

package.json exports picks the build by condition: node (Node 22.12 or later) loads the native addon built with napi-rs; deno (Deno 2.6 or later) imports the WebAssembly module as a module source, so loading needs no permission; browser and any other runtime fetch it by URL with top-level await. The modules are ES modules; on Node, require('cleanrules') works too, through require(esm). Both builds have the same classes, methods, options, errors and messages; the WebAssembly objects also have free(), and [Symbol.dispose]() works with both, so using does. Objects of one build do not mix with the other's (a TypeError says so). Where no prebuilt addon fits the machine, node --conditions=browser runs the WebAssembly build.

Building conditions#

A condition is data, a tree of nodes the core evaluates, never a JavaScript function. fuzzytool's operators &, | and ~ are the methods .and(), .or() and .not(); every node is built by the core's constructors, so a node it refuses fails at once with an ExpressionError.

constF: FieldRoot

The start of every field path: F.customer.age.ge(18). Every property is a key, except a field's own members; then is never a field (so await never takes one for a promise), and an index is refused: write F.items.at(0).price. F as Fields<Order> types it after the input, for completion and checked keys (types only: at run time it is F).

functionfield(...path: Array<string | number>): FieldRef

A field by its path: field('items', 0, 'price'). Strings are keys, numbers are indices.

functionconstant(value: Constant): Const

A constant, where no node is involved: constant(true). Values next to a node become constants by themselves (F.x.gt(5)).

functionand, or, not(...operands: Expr[]): Expr

and(a, b, ...) and or(a, b, ...) need at least two conditions; not(x) negates one. The same as the methods.

classExpr

A node of a condition tree, immutable: assigning to one throws a TypeError. Comparing with null is refused (test missing values with isNull()); JavaScript operators are refused too: F.age >= 18 and F.age + 1 throw an ExpressionError, and === compares objects (use sameAs).

Comparisons and connectives

Missing or null; never unknown.

Rules and rule sets#

classRule(name: string, when: Expr, then?: Payload | null, options?: RuleOptions)

A named condition and its payload; immutable and checked as it is built (RuleDefinitionError, ExpressionError or RegistryError). The third argument is the payload (an object or a Map of nodes or constants, in order); options go in the fourth.

Options

priority
Used by the priority hit policy; higher wins. 0 by default.
tags
Labels; kept sorted and without repeats.
description
A description.
metadata
Free-form data only (owner, ticket...).
do
The action: a function that run calls, or the name of one, which is data and bind resolves.

Members

name, when, then, priority, tags, description, metadata
The rule, as the core keeps it.
do, actionName
The action's code (given or bound), and its name if it names one.
toJSON()
The rule document { version, rule }; an UnsupportedError for an action that is code without a name.

classRuleSet(rules: Iterable<Rule>, options?: RuleSetOptions)

Rules evaluated together under a hit policy; immutable, iterable and indexed by name. Hit policies and aggregates are named as in the format, in any case; an unknown option is a TypeError.

Options

hitPolicy
'first' (default), 'priority', 'unique', 'any', 'rule_order' or 'collect'.
aggregate
With collect: 'sum', 'min', 'max' or 'count'.
logic
'boolean' (Kleene's three-valued logic) by default.
strict
Throw instead of giving unknown for missing fields and type mismatches.

Members

rules, length, [Symbol.iterator]
The rules, in order.
get(name), has(name), rule(name)
get gives undefined for an unknown name, like Map; rule throws a RuleNotFoundError listing the rules.
hitPolicy, aggregate, logic, strict, fieldPaths()
Its configuration and the paths it reads; native data is read along these only.
evaluate(data)
A Decision; in strict mode, an EvaluationError for a missing field or a type mismatch.
evaluateMany(rows)
One decision per input; an error names its row.
readDecision(text, { format, limits }?)
A recorded decision (JSON or YAML), checked against the rule set.
bind(actions)
A rule set whose named actions are resolved in an object or Map of functions; every named action is checked.
run(data)
Evaluate, then call the selected rules' actions in rule order (see Decisions).
summary()
A Summary.
toJSON()
The rule set document { version, ruleset }.

Decisions and actions#

classDecision

The outcome of evaluating a rule set on one input; immutable.

Members

ruleset, hitPolicy
Where it comes from.
results
Every rule's RuleResult, in rule order.
selected, fired
The results the hit policy selected, and the names of the rules that fired.
output
The winner's payload or the aggregate, as native values; null when nothing was selected. Throws a HitPolicyError for rule_order, and collect without an aggregate.
outputs, aggregated
The payloads of the selected rules, in rule order; the aggregate's values with collect.

An Explanation, and one rule's (a RuleNotFoundError for an unknown name).
toJSON()
The decision document; RuleSet.readDecision reads it back.

classRuleResult

One rule's result.

Members

rule, fired, truth
The rule, whether it fired, and the truth of its condition ('true', 'false', 'unknown').
output
Its evaluated payload when the hit policy needed it; otherwise null.

classActionContext

What an action receives. evaluate never calls actions; run refuses unbound names before reading anything, evaluates, and calls the selected rules' actions in rule order. Actions are synchronous: what they return is ignored, except a promise, which fails the run. An action that throws stops the run with an ActionError whose cause is what it threw, context.executed the rules whose actions ran, and decision the decision.

Members

rule, data, result, output, decision
The rule, the input as given, its result, its evaluated payload and the decision.
tree
The ResultTree of the rule's condition, made from the input already read.

Documents#

Formats are 'json' (the default), 'yaml', 'text' (the rule syntax) and 'csv' (decision tables); a file's extension (.json, .yaml, .yml, .rules, .csv) gives its format unless format says. Reading is the core's, strict and bounded: errors have a JSON Pointer or a line and column, and limits takes maxSize, maxNesting, maxDepth, maxTableSize, maxYamlSize and maxTextSize.

functionloads(text: string | Uint8Array, { format, limits, actions }?): Expr | Rule | RuleSet | DecisionTable

Read a document. A rule's action is the name the document gives it, unbound unless actions binds it. Rules read from documents are the core's own, so they write back exactly.

functiondumps(value, { format, omitActions }?): string

The canonical document of a condition, rule, rule set or table. A rule whose action is code cannot be written (UnsupportedError) unless omitActions.

functionload, dump(path: string | URL, options?): Promise

loads of a file and dumps to a file, in Node (through process.getBuiltinModule) and Deno (with --allow-read, --allow-write). In browsers they reject with an UnsupportedError that names loads and dumps.

functionruleFromText(text, { do, actions, limits }?): Rule

One rule in the text syntax (fuzzytool's verb); rule_1 without a RULE line. do is a function a name in the text (DO notify) is bound to.

Decision tables and result trees#

classDecisionTable(header: Iterable<HeaderItem>, rows: Iterable<Iterable<Cell>>, options?)

A decision table and the rule set it compiles into, built from a header and rows as a spreadsheet holds them, or read with loads(text, { format: 'csv' }). A header item is a CSV header field's text ('RULE', 'PRIORITY', 'THEN key', an input expression), an input Expr, or a TableOutput. A string cell is read as in the CSV ('> 5', '-', and "'VIP'" for the string); null is empty; any other value is a constant. Errors point into the grid (/header/<c>, /rows/<r>/<c>).

Members

hitPolicy, aggregate, logic, strict
As a rule set's; 'output_order' is also a policy here.
inputs, outputs, rows
The input Exprs, the TableOutputs (name, values) and the TableRows (name, priority, description, inputs, outputs).
ruleset
The RuleSet it compiles into.
evaluate, evaluateMany, summary, toJSON()
As a rule set's.

functionevaluateTree, evaluateValueTree(node: Expr, data: unknown, { logic, strict }?): ResultTree

Evaluate one condition (or one value node) on native data. A ResultTree has node, truth (for a condition) or value (for a value), reason, children and toJSON(); a between has its two half comparisons as children.

Values#

Native data is read along the rule set's field paths only, each object once. JavaScript has one number type, so a few values need a marker:

JavaScriptValue
null, an Invalid Date, NaN; undefinednull; missing
an integer number within ±(2⁵³ − 1); any other numberint; float (-0 and infinities included)
float(x), bigint, decimal("0.10")float, int (null beyond 64 bits), exact decimal (null beyond 38 digits)
date(y, m, d), datetime(...); Temporal.PlainDate, Temporal.PlainDateTimedate, naive datetime
Date, Temporal.Instant; Temporal.ZonedDateTimeaware datetime in Z; in its zone
Array; Map, plain objects and class instanceslist; map (own enumerable string keys and getters)
bytes, Set, functions, anything elseopaque

Values come back the same in Node, Deno and browsers: ints as number (beyond 2⁵³, bigint), floats as number, decimals as Decimal (its text), dates as LocalDate and NaiveDateTime, aware datetimes as ZonedDateTime (local fields, offsetSeconds, timeZone, epochMicroseconds, toDate(), toTemporal(), and the RFC 9557 text as toString()), lists as arrays and maps as frozen plain objects. A rule never reaches into the program: a field never reads a symbol, a # field, a method, a prototype, constructor or __proto__. A getter that throws gives a null with reason read_error (in strict mode, an EvaluationError).

functiondecimal, float, date, datetime

decimal('0.10'): an exact decimal. float(2): the number as a float, not an int. date(2026, 11, 4): a date (months from 1). datetime(2026, 11, 4, 9, 30): a naive datetime. They return the marker classes Decimal, Float, LocalDate and NaiveDateTime, recognised by a brand, so markers made by another copy of the package work too.

Initialising the WebAssembly module yourself#

cleanrules/wasm has the exports of cleanrules, the native classes in native, and init(source), for bundlers and CDNs that serve the module from a URL of their own. Importing it loads nothing; until init resolves, using what needs the module throws an Error whose code is 'ERR_CLEANRULES_NOT_INITIALISED', and version and FORMAT_VERSION are undefined. Calling init twice is harmless.

browser.ts
import { init, F, Rule, RuleSet } from 'cleanrules/wasm'

// A URL, a Request or Response, the bytes, or a compiled WebAssembly.Module.
await init(new URL('cleanrules_bg.wasm', import.meta.url))
// With Vite: import wasmUrl from 'cleanrules/wasm/cleanrules_bg.wasm?url'; await init(wasmUrl)

With the plain cleanrules entry, webpack 5 and Vite copy the module in builds (in Vite's development server, add optimizeDeps: { exclude: ['cleanrules'] }); esbuild does not follow new URL(...), so copy wasm/cleanrules_bg.wasm next to the bundle or use cleanrules/wasm.

Pitfalls#

Most of these come from JavaScript itself. The program below shows the first five, and its output is real.

  • An index is not a property. Property names are strings in JavaScript, so F.items[0] is ambiguous and throws, with the fix: write F.items.at(0) or field('items', 0). .at('0') is the key "0".
  • Fields named like a method (and, or, not, path, tag...) or like a member of Object.prototype (constructor, valueOf, toString...) are reached with .at('and') or field('x', 'and').
  • The third argument of new Rule is the payload. new Rule('vip', cond, { priority: 10 }) makes an output called priority; write new Rule('vip', cond, null, { priority: 10 }).
  • 1890.0 is the int 1890. JavaScript has one number type, and an integral number reads as an int. Wrap it in float(x) where a float matters, as in the fraud example.
  • JSON.stringify of toJSON() writes a float that holds an integer as {"$float": 1}, so it reads back, but it loses the sign of -0 and puts integer-like keys first, as any plain object does (a payload { b, "10" } becomes { "10", b }, and a decision with that payload no longer matches its rule). dumps, and the native layer's write() and explain('json'), write documents exactly. Give such payloads as a Map.
  • cleanrules/wasm needs await init() before anything that uses the module; the plain cleanrules entry initialises itself.
  • JavaScript operators are refused: F.age >= 18 and F.age + 1 throw an ExpressionError, and === compares objects (use sameAs). `${node}` and String(node) give the node's text.
  • Actions are synchronous. A promise returned by an action fails the run with an ActionError.
pitfalls.tsJavaScript binding · runs
import { F, Rule, constant, dumps, field, float } from 'cleanrules'

// 1. An index is not a property: F.items[0] throws, with the fix.
try {
  F.items[0]
} catch (err) {
  console.log((err as Error).name, '-', (err as Error).message)
}
console.log(String(F.items.at(0).price.gt(10)), '|', String(field('items', 0, 'price').gt(10)))

// 2. A field named like a method (and, or, not, path, tag...) needs .at().
console.log(String(F.flags.at('and').eq(true)))

// 3. The third argument of new Rule is the payload; options go fourth.
const oops = new Rule('vip', F.years.gt(5), { priority: 10 })
const meant = new Rule('vip', F.years.gt(5), null, { priority: 10 })
console.log(oops.priority, Object.keys(oops.then), '|', meant.priority, Object.keys(meant.then))

// 4. 1890.0 is the int 1890 in JavaScript: float() keeps a float.
console.log(dumps(F.amount.gt(1890)), '|', dumps(F.amount.gt(float(1890))))

// 5. JSON.stringify loses the sign of -0 and puts integer-like keys first; dumps keeps both.
//    A payload with such keys goes in a Map: an object literal reorders them already.
const rule = new Rule('r', F.x.gt(0), new Map([['b', constant(-0)], ['10', constant(1)]]))
console.log(JSON.stringify(rule.toJSON()))
console.log(dumps(rule))
