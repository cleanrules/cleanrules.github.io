Python pitfalls

Conditions are data: F.age >= 18 does not compare anything, it builds a node that the core evaluates later. polars and SQLAlchemy work the same way. It also means a few everyday Python idioms behave differently. Each pitfall below raises a clear ExpressionError with a hint, or has a simple alternative.

Use &, | and ~, not and, or and not#

Python's and, or, not and if ask for a real True or False, which a node cannot give. cleanrules raises instead of guessing:

PythonPython binding · runs
from cleanrules import F

(F.age >= 18) and (F.country == "ES")
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: a condition node cannot be used as a Python bool: F.age >= 18
hint: combine conditions with &, | and ~ (not and/or/not, not `if`); write ranges as F.x.between(low, high) instead of chained comparisons; use F.x.is_in([...]) instead of `in`

Write (F.age >= 18) & (F.country == "ES").

Parenthesize comparisons#

& and | bind more tightly than > and == in Python, so F.a > 1 & F.b < 2 means F.a > (1 & F.b) < 2:

PythonPython binding · runs
F.a > 1 & F.b < 2
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: a value ('const') cannot be an operand of 'and', in `Const(1)`

No chained comparisons#

Python expands 0 < F.x < 10 to (0 < F.x) and (F.x < 10), which runs into the and problem. Use F.x.between(0, 10, closed="none").

PythonPython binding · runs
0 < F.x < 10
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: a condition node cannot be used as a Python bool: F.x > 0
hint: combine conditions with &, | and ~ (not and/or/not, not `if`); write ranges as F.x.between(low, high) instead of chained comparisons; use F.x.is_in([...]) instead of `in`

Test for missing values with is_null()#

Missing values are unknown under three-valued logic, so x == None could never be true:

PythonPython binding · runs
F.email == None  # noqa: E711
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: comparing with None is never true: F.email == None
hint: missing values are unknown; test for them with .is_null()

Compare nodes with same_as, not ==#

== builds a node, so it cannot tell you whether two nodes are equal:

PythonPython binding · runs
a, b = F.price * 2, F.price * 2
print(a == b)
print(a.same_as(b), a is b)
Output
F.price * 2 == F.price * 2
True False
Instead ofUse
node1 == node2node1.same_as(node2)
node in list_of_nodesany(node.same_as(n) for n in list_of_nodes)
{node: ...} keyed by structure{node.structural_key(): ...}
assert node1 == node2 in testsassert node1.same_as(node2)

Nodes hash by identity: sets and dicts of nodes work as long as you look up the very same objects. list.index, list.remove, list.count, sorted, min and max compare with == or <, so avoid them on nodes. WeakKeyDictionary does not work with nodes.

Nodes are not collections#

Without this error, Python would iterate F.orders[0], F.orders[1], … forever. Index explicitly, and test membership against constants with is_in:

PythonPython binding · runs
list(F.orders)
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: condition nodes are not iterable: F.orders
hint: use F.items[0] for one element and F.x.is_in([...]) for membership
PythonPython binding · runs
"vip" in F.tags
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: `in` cannot test membership in a condition node: 'vip' in F.tags
hint: use F.x.is_in([...]) to test a value against a set of constants

F.tags.contains("vip") is not list membership either: contains, starts_with and ends_with work on strings and take literal text. polars' str.contains, by contrast, treats its argument as a regular expression by default; use matches for patterns.

Field names that clash with node attributes#

Any public attribute of a field keeps its meaning after a dot: path, tag, kind, children, walk, same_as, structural_key, field_paths and the methods is_in, between, is_null, matches, starts_with, ends_with, contains and abs. So F.product.tag is the node's tag, a string, and comparing it is plain Python. When that ends up next to &, cleanrules catches it:

PythonPython binding · runs
(F.price > 5) & (F.product.tag == "sale")
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: cannot combine a condition with a Python bool (False)
hint: if you compared a field named like a node attribute (kind, tag, path, ...), use item access such as F.x["kind"]; for a constant write Const(True)

Beware the silent case: F.a == F.b.kind builds F.a == 'any'. Use item access for such names, and for Python keywords, names starting with an underscore, and names with spaces. The first segment after F is always a field, so F.kind works:

PythonPython binding · runs
print(F.product["tag"] == "sale")
print(F.kind == "a")
print(F["class"] == "b")
Output
F.product['tag'] == 'sale'
F.kind == 'a'
F['class'] == 'b'

Calling a field path#

Calling something that is not a method raises, with a suggestion when the name is close to one (isin, startswith, isnull, is_between):

PythonPython binding · runs
F.country.isin(["ES"])
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: F.country.isin is a field path, not a method
hint: did you mean .is_in(...)?

No polars-style namespaces#

Methods live on the field itself: F.name.starts_with("A"), not F.name.str.starts_with("A"). After the first segment, str, dt, list, arr, struct and cat raise; reach a real field with one of those names as F.x["str"].

PythonPython binding · runs
F.name.str.starts_with("A")
Output
Traceback (most recent call last):
  ...
AttributeError: 'str' looks like a polars namespace; cleanrules methods live on the field itself (e.g. F.x.starts_with(...)). For a field named 'str' use F.x['str']

numpy and pandas values#

numpy scalars work on either side and are converted to constants, so np.int64(5) < F.x builds F.x > 5:

PythonPython binding · runs
import numpy as np

print(np.int64(5) < F.x)
Output
F.x > 5

Arrays, Series and DataFrames are not constants. np.array([1, 2]) == F.x and df["a"] > F.x raise instead of comparing element by element:

PythonPython binding · runs
np.array([1, 2]) == F.x
Output
Traceback (most recent call last):
  ...
cleanrules.errors.ExpressionError: a ndarray cannot be a constant: array([1, 2])
hint: constants are None, bool, int, float, Decimal, str, date or datetime

To evaluate rows, pass df.to_dict("records") to evaluate_many, or the rows themselves (reading Python objects). To check whole columns at once, vectorized validation is planned (phase I).

fuzzytool terms go on the right#

Until fuzzytool 0.8, score["poor"] & (F.x > 2) builds a fuzzytool node instead of a cleanrules one, because fuzzytool's & does not return NotImplemented for foreign types. Put the cleanrules condition first, (F.x > 2) & score["poor"]. Interoperability with fuzzytool terms is planned (phase J).
