Manual / Chapter 17

C++ API

cleanrules.hpp is a header-only C++17 layer over the C ABI: the same engine and the same concepts (ruleset, decision, explain, summary), with handles that free themselves, values built from C++ data, and errors as exceptions or as values. Everything lives in namespace cleanrules; the examples write namespace cr = cleanrules;.

Built from the repository. The CMake package, the Conan recipe and the vcpkg overlay port all build from a checkout (installation); nothing is in ConanCenter or the vcpkg registry yet. This page is written from bindings/cpp/include/cleanrules.hpp and its README at commit 01ea4a4, and building in code at commit a1758c5. The C++ layer reads rules as documents (JSON, YAML, the rule syntax or CSV tables), and can also build them node by node with the constructors of the C ABI; it has no operator syntax like Python's F.

A first program#

Rules in the rule syntax, an input built from C++ values, which rules fired, an exact decimal, an action as a lambda, an error as a value, and the summary. Compiled as C++17 against the installed package and run:

api.cppC++ binding · runs
#include <cleanrules.hpp>
#include <iostream>

namespace cr = cleanrules;

int main() {
    auto rules = cr::ruleset::read(R"(
        HIT POLICY priority
        RULE vip PRIORITY 10
        IF customer.years > 5 AND order.total > 1000
        THEN discount = 0.15
        DO notify_sales
        RULE loyal PRIORITY 5
        IF customer.years > 2
        THEN discount = 0.05
    )", cr::format::text);
    std::cout << rules.size() << " rules, hit policy " << rules.hit_policy() << "\n";

    auto input = cr::value::map({
        {"customer", cr::value::map({{"years", 7}})},
        {"order", cr::value::map({{"total", cr::value::decimal("1500.00")}})},
    });
    auto decision = rules.evaluate(input);
    for (std::size_t i = 0; i < decision.size(); ++i) {
        std::cout << decision.rule_name(i) << (decision.fired(i) ? " fired" : " did not fire") << "\n";
    }
    std::cout << "discount " << decision.output()["discount"].as_decimal() << "\n";

    // Actions are C++ callables, registered by the name the rules give them.
    cr::actions actions;
    actions.add("notify_sales", [](cr::action_call &call) {
        std::cout << "notify_sales for " << call.rule_name() << ", years "
                  << call.input()["customer"]["years"].as_int() << "\n";
    });
    (void)rules.run(actions, input);

    // Errors as values: an input that is not JSON.
    cr::error_info error;
    if (!rules.evaluate_json(R"({"customer": )", error)) {
        std::cout << cr::name(error.code()) << ": " << error.message() << "\n";
    }
    std::cout << rules.summary() << "\n";
}
Output
2 rules, hit policy priority
vip fired
loyal fired
discount 0.15
notify_sales for vip, years 7
format_error: expected a value, found the end of the document
Rule set: 2 rules, hit policy priority, logic boolean
  priority  name   condition                                  outputs
        10  vip    customer.years > 5 AND order.total > 1000  discount DO notify_sales
         5  loyal  customer.years > 2                         discount
Fields read (2):
  customer.years  conditions of vip, loyal
  order.total     conditions of vip
Outputs: discount

The summary is the text every language prints. The worked examples have a C++ tab each, and docs/examples/discounts.cpp in the repository does more.

Building and linking#

CMakeLists.txt
find_package(cleanrules CONFIG REQUIRED)       # with CMAKE_PREFIX_PATH set to the install prefix
target_link_libraries(app PRIVATE cleanrules::cleanrules)   # C++17; cleanrules::c for C

add_subdirectory(path/to/bindings/cpp) gives the same two targets. The CMake project builds the C library with cargo, so it needs a Rust toolchain and CMake 3.21. Its options include CLEANRULES_SHARED (the shared library instead of the static one), CLEANRULES_RUST_TARGET (cross-compiling), CLEANRULES_MSVC_STATIC_CRT and CLEANRULES_SANITIZERS (such as address,undefined for the tests). ctest runs the API tests, the header without exceptions, the installed package, and every conformance vector through this header: 2,508 through JSON, and 1,952 with input built from C++ values.

Versions#

constantheader_abi_version: std::uint32_t

The C ABI this header was written for. Compare it with abi_version(), the ABI of the library linked in, as docs/examples/discounts.cpp does.

functionversion, format_version() noexcept

version() is the library's version (a std::string_view); format_version() the version of the JSON format it reads and writes (1).

Errors#

As in std::filesystem, each call that can fail has two overloads: one that throws a cleanrules::error, and one that takes an error_info & last and never throws one. A failed call then returns an empty handle (false), an empty text or a zero, and a successful one clears the error_info.

errors.cppC++ binding · runs
#include <cleanrules.hpp>
#include <iostream>

namespace cr = cleanrules;

int main() {
    auto adult = cr::ruleset::read(R"(
        STRICT
        RULE adult IF customer.age >= 18
    )", cr::format::text);
    auto input = cr::value::map({{"customer", cr::value::map({{"name", "Ana"}})}});

    // An exception: missing_field_error derives from evaluation_error.
    try {
        (void)adult.evaluate(input);
    } catch (const cr::evaluation_error &e) {
        std::cout << "code:    " << cr::name(e.code()) << "\n";
        std::cout << "parent:  " << cr::name(cr::parent(e.code())) << "\n";
        std::cout << "message: " << e.what() << "\n";
        std::cout << "json:    " << e.json() << "\n";
    }

    // Or a value: the error_info overloads never throw a cleanrules::error.
    cr::error_info error;
    if (!adult.evaluate(input, error)) {
        std::cout << "is an evaluation_error: " << std::boolalpha
                  << error.is(cr::errc::evaluation_error) << "\n";
    }
}
Output
code:    missing_field
parent:  evaluation_error
message: missing field customer.age
json:    {"code":"missing_field","message":"missing field customer.age","rule":"adult","path":["customer","age"],"node":{"op":"field","path":["customer","age"]}}
is an evaluation_error: true

classerror : std::runtime_error

The base of the exceptions, one class per code of spec/errors.md: format_error (also for unsupported_version, limit_exceeded and decision_mismatch), expression_error, rule_definition_error, rule_syntax_error, registry_error, rule_not_found_error, evaluation_error (above missing_field_error, type_mismatch_error and hit_policy_error), action_error, unsupported_error, invalid_argument_error for a misuse of the API such as a moved-from handle, and internal_error, a bug in cleanrules.

Members

what()
The message, written by the core.
code()
The errc.
hint()
How to fix it, or empty.
json()
The error's JSON form (spec/errors.md).
info()
The error_info.
decision()
On an action_error: a copy of the decision being run; std::rethrow_if_nested gives what the action threw.

classerror_info

An error as a value: false when nothing failed.

Members

explicit operator bool
Whether a call failed.
code(), is(ancestor)
The errc, and whether it is ancestor or below it.
message(), hint(), json()
As above, as std::string_views.
cause()
The exception an action threw, as a std::exception_ptr.
decision()
The decision of an action error.
clear()
Reset it.

enum classerrc

ok, the codes of spec/errors.md (format_error ... unsupported), invalid_argument and internal_error. name(code) gives its name, parent(code) its parent in the hierarchy, and is(code, ancestor) tests it.

Built without exceptions (-fno-exceptions, /EHs-c-, or with CLEANRULES_NO_EXCEPTIONS defined), only the error_info overloads exist. Both kinds of translation unit may share a program: the header puts each in its own inline namespace.

Values#

classvalue

An owned value: copies deeply (null reasons and opaque tokens included) and moves cheaply. It converts from nullptr, bool, integers, double, UTF-8 strings (const char *, std::string, std::string_view), date, naive_datetime, aware_datetime and opaque; other pointers and character types are not values.

Factories

value::map({{"k", v}, ...}), value::record({...})
A map, or a record (a map whose entries also have positions); value::map() is empty, filled with insert.
value::list({...}), value::list_of_size(n)
A list, or n nulls to set.
value::decimal("19.90")
An exact decimal; beyond 38 digits, a null with decimal_overflow.
value::null(reason, detail)
A null with a reason.
value::from_json(text, limits?)
A value read from JSON, as data.
value::make(x, error)
The checked constructors, which report instead of throwing.

Changing

set(index, item), insert(key, item)
Fill a list or a map, in place.
release(), value::adopt(raw)
Give up or take ownership of the C handle.

classvalue_ref

A borrowed view, valid until the value it comes from changes, moves or is destroyed; clone() makes it a value. Read from a temporary, the accessors return owned copies instead, so auto label = decision.output()["label"].as_string(); is a std::string.

Accessors (also on value)

kind(), is_null(), is_record(), size()
What it is (value_type) and how many items or entries.
v[i], v["key"], entry(i)
A list item or a map value, empty (false) when there is none; a map entry by position.
as_bool(), as_int(), as_float()
Scalars.
as_decimal()
A decimal's canonical text, such as 0.15.
as_string()
A std::string_view into the value.
as_date(), as_naive_datetime(), as_aware_datetime(), as_opaque(), as_null()
Dates, an opaque value's type name and token, a null's reason.
to_json()
The value as JSON.

structdate, naive_datetime, aware_datetime, opaque

date{y, m, d}; naive_datetime{y, m, d, h, min, s, us}; aware_datetime{seconds, microsecond, offset_seconds, zone}, an instant since the epoch with its UTC offset and IANA zone (empty for a fixed offset); opaque{type_name, token}, a token of your own for native data with no equivalent.

Documents and rule sets#

classruleset

A rule set, ready to evaluate. Immutable: use it from as many threads as you like.

Reading

ruleset::read(text, format, limits?)
A rule set, a decision table (compiled) or one rule, in format::json, yaml, text (the rule syntax) or csv.
ruleset::from_document(doc)
The rule set a document gives.

What it is

size(), rule_name(i)
The rules.
hit_policy(), aggregate(), strict()
Its configuration.
field_paths()
The paths it reads, as a list value.
write(format = json), summary(format = text)
The document, and the summary.

Evaluating

evaluate(input, limits?)
A decision; it keeps its rule set alive and a copy of the input.
evaluate_json(text, limits?)
The same, on an input given as JSON.
evaluate_many(inputs, limits?)
A batch, one decision per item of a list; the first failure gives the error, with its row.
run(actions, input)
Evaluate, then call the selected rules' actions in rule order.
check_actions(actions)
Whether every action the rules name is registered.
read_decision(text, format)
A recorded decision, checked against the rule set.

classdocument

A document in any format: a condition, a rule, a rule set or a decision table. document::read(text, format, limits?), content() (a document_content) and write(format = json), the canonical form.

classlimits

Limits for reading documents and inputs, the defaults at first: set(limit::max_size, n) (and max_nesting, max_depth, max_table_size, max_yaml_size, max_text_size), get(which). Set them before sharing them.

Decisions#

classdecision, decision_ref

What a rule set made of one input, or a recorded decision read with its rule set. A decision_ref is borrowed from a batch or an action call; clone() keeps it longer.

Members

size()
The number of rules.
fired(i), truth(i), rule_name(i)
Each rule's result: whether it fired, its truth (true_, false_, unknown), its name.
selected()
The positions of the selected rules.
output(), outputs()
The single output (a map, the aggregate, or a plain null), or the list of outputs; output() throws a hit_policy_error for policies with several.
rule_output(i)
A rule's evaluated payload, or a plain null.
output_json(), outputs_json()
The same, as JSON.
write(format = json)
The decision document.
explain(format = text)
The explanation: the text every language prints, or a JSON or YAML document.

classbatch

The decisions of evaluate_many: size(), empty(), b[i] and iteration give decision_refs that live as long as the batch.

Building in code#

The C ABI's constructors, added for the Java binding, build nodes, rules and rule sets in code; the core checks each one as it is made (an expression_error or a rule_definition_error). The rules of the first program, built this way and run:

building.cppC++ binding · runs
#include <cleanrules.hpp>
#include <iostream>

namespace cr = cleanrules;

int main() {
    auto years = cr::node::field(cr::value::list({"customer", "years"}));
    auto total = cr::node::field(cr::value::list({"order", "total"}));
    auto vip = cr::rule::make("vip", cr::node::and_({cr::node::compare("gt", years, cr::node::constant(5)),
                                                     cr::node::compare("gt", total, cr::node::constant(1000))}))
                   .with_payload("discount", cr::node::constant(cr::value::decimal("0.15")))
                   .with_priority(10);
    auto loyal = cr::rule::make("loyal", cr::node::compare("gt", years, cr::node::constant(2)))
                     .with_payload("discount", cr::node::constant(cr::value::decimal("0.05")))
                     .with_priority(5);
    auto rules = cr::ruleset::make({vip, loyal}, cr::ruleset_settings{"priority", {}, {}, false});

    auto decision = rules.evaluate(cr::value::map({
        {"customer", cr::value::map({{"years", 7}})},
        {"order", cr::value::map({{"total", 900}})},
    }));
    std::cout << decision.output_json() << "\n" << decision.explain() << "\n";
    std::cout << rules.write(cr::format::text);
}

Compiled as C++17 against cleanrules.hpp and the static C library built with cargo at commit a1758c5, and run.

functionsnode::field, constant, compare, arith, and_, or_, not_, is_in, between, is_null, matches, string_test, abs, neg

Nodes by tag (compare("gt", a, b), arith("mul", a, b), string_test("ends_with", a, text)); field takes a list of keys and indexes, never split at dots. A node gives its tag(), kind(), children(), detail(), same_as(other) and hash(), with std::hash and std::equal_to for unordered containers.

classrule

rule::make(name, when) and its with_payload, with_priority, with_tags, with_description, with_metadata and with_action steps, each a new rule; rule::from_text(text) reads one in the rule syntax. A rule gives name(), description(), action_name(), priority(), when(), payload(), tags() and metadata(). ruleset::make(rules, ruleset_settings{hit_policy, aggregate, logic, strict}) makes a rule set; rule_at(i) and rule_position(name) (a rule_not_found_error otherwise) read it; document::from_condition and from_rule make documents to write. decision::explanation() gives the explanation as a value.

Actions#

classactions

An action registry: names mapped to callables (std::function<void(action_call &)>), which it keeps. add(name, fn) registers one; register them all before running. A finished registry may be used from several threads, whose actions then run concurrently.

classaction_call

One call of an action, valid during the call only. An action that throws, or calls fail, stops the run with an action_error thrown over it.

Members

decision()
The decision being run (a decision_ref).
rule(), rule_name()
The position and name of the rule whose action is called.
input()
The input, as the decision keeps it.
fail(reason), failed()
Fail the action, saying why.

Nodes and tables#

classnode

One condition or value, read on its own: node::read(text, format) (JSON, YAML or the rule syntax, such as order.total * 0.9), write(format = json), evaluate_tree(input, logic = "boolean", strict = false) and evaluate_value_tree(input, strict = false), which return the result tree as JSON.

classgrid, table_settings

A decision table built row by row: grid::make(header, table_settings{hit_policy, aggregate, logic, strict}) with a list of header texts, push_row(row) with a list of cells (a string is read as a CSV field, null is an empty cell, any other value a constant), and finish(), which checks it and returns a document for ruleset::from_document.

Threads and ownership#

Rule sets, documents, decisions, nodes and batches never change once made: share them between threads. Values, limits, grids and action registries change while they are built; finish them first. Every handle frees its C handle; c_ptr() lends it to C code, and value::adopt, decision::adopt and value::release() move ownership across. The header includes cleanrules.h, so the whole C ABI stays available.
