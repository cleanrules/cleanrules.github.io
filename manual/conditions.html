Manual / Chapter 04

Writing conditions

A condition is a tree of nodes that the core evaluates later. You build it with F, Python operators and a handful of methods; the core checks every node as it is built. This chapter covers each kind of node, constants of every type, and how to inspect a tree.

Fields: F and Field#

F starts a path into the input. Attribute access adds a key, item access adds a key that is not a valid Python name, and an integer indexes a list. Field(...) builds the same node from its segments.

PythonPython binding · runs
from cleanrules import F, Field

print(F.customer.age)
print(F["customer"]["first name"])
print(F.orders[0].total)
print(Field("orders", 0, "total").path)
Output
F.customer.age
F.customer['first name']
F.orders[0].total
('orders', 0, 'total')

A path reads a key of a mapping, or an index of a list. A missing key gives a missing value and a None gives a null; both make comparisons unknown (reasons). Some names cannot follow a dot because they already mean something on a node (tag, kind, path, the method names, and names starting with _): write them with item access, F.product["tag"]. The pitfalls chapter lists them.

Comparisons#

==, !=, <, <=, > and >= build comparison nodes. A Python value next to a node becomes a constant. When the constant is on the left, Python asks the node to reflect the comparison, so the field stays on the left. Two fields can be compared directly.

PythonPython binding · runs
from cleanrules import F

adult = F.customer.age >= 18
print(adult, "|", adult.tag, adult.kind)
print(5 < F.x)             # Python reflects it: the field stays on the left
print(F.price <= F.budget)  # two fields
Output
F.customer.age >= 18 | ge condition
F.x > 5
F.price <= F.budget

Every node has a tag (its operator in the JSON format) and a kind: condition (true, false or unknown), value (a number, a string…), or any for a field or a boolean constant, whose kind depends on the data. A rule's when must be a condition or any; its payload values must be values or any.

Values compare within their type group: numbers (ints, floats and decimals compare with each other, exactly), strings, booleans (== and != only), dates, naive datetimes and aware datetimes. Comparing across groups is a type mismatch: unknown, or an error in strict mode. == on strings is exact; there is no case folding.

Combining conditions: &, |, ~#

Use & for and, | for or and ~ for not, never Python's and, or and not, which need a real boolean and raise ExpressionError (pitfalls). Parenthesize comparisons: in Python, & and | bind more tightly than >.

PythonPython binding · runs
spain = F.country == "ES"
cond = (adult & spain) | ~F.blocked
print(cond)
print(cond.tag, [child.tag for child in cond.children()])
Output
((F.customer.age >= 18) & (F.country == 'ES')) | ~F.blocked
or ['and', 'not']

The repr of a node is Python that builds the same tree, so you can paste it back. Under three-valued logic, & is false as soon as one operand is false, even if another is unknown, and | is true as soon as one is true (truth tables).

Membership, ranges, nulls and strings#

PythonPython binding · runs
print(F.country.is_in({"PT", "ES", "ES"}))
print(F.age.between(18, 65))
print(F.age.between(18, 65, closed="left"))
print(F.email.is_null())
print(F.email.matches(r"(?i)^[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}$"))
print(F.sku.starts_with("EU-"))
print(F.note.contains("urgent"))
Output
F.country.is_in(['ES', 'PT'])
F.age.between(18, 65)
F.age.between(18, 65, closed='left')
F.email.is_null()
F.email.matches('(?i)^[a-z0-9._%+-]+@[a-z0-9.-]+\\.[a-z]{2,}$')
F.sku.starts_with('EU-')
F.note.contains('urgent')
is_in(values)
Membership in a collection of constants of one type group (no None). The values are kept sorted and without duplicates, so the order you write them in does not matter.
between(low, high, closed="both")
A range. closed is "both", "left", "right" or "none", the same names as polars. Bounds may be constants or nodes. Explanations report a between as its two halves, so they can say which bound failed.
is_null()
True when the value is missing or null, false otherwise; it is never unknown. Use it instead of == None, which raises. In strict mode a missing field raises even under is_null; an explicit None does not (strict mode and nulls).
matches(pattern)
A regular-expression search (not a full match: anchor with ^ and $). (?i) makes it case-insensitive.
starts_with(text), ends_with(text), contains(text)
Literal string tests, not patterns. contains is substring search on strings, not list membership: use is_in for that.

Regular expressions#

Patterns use the syntax of Rust's regex crate, in every language. Matching runs in time linear in the input, which makes rules from untrusted sources safe to evaluate; the price is that look-around and backreferences are not supported. A pattern that does not compile is rejected when the node is built:

PythonPython binding · runs
try:
    F.pin.matches(r"^(?=.*\d).{8,}$")
except ExpressionError as err:
    print(err)
Output
the pattern "^(?=.*\\d).{8,}$" is not valid: regex parse error:
    ^(?=.*\d).{8,}$
     ^^^
error: look-around, including look-ahead and look-behind, is not supported
hint: patterns use the syntax of Rust's regex crate: no lookaround, no backreferences

Most everyday syntax works as in Python's re: classes, \d, \b, quantifiers, groups, alternation, (?i). Unicode is on by default, so \d and \w match beyond ASCII.

Arithmetic#

+, -, *, /, unary - and abs() build value nodes. They work on numbers; compare the result to get a condition, or use it as a payload value.

PythonPython binding · runs
ratio = F.debt / F.income
print(ratio > 0.45)
print(abs(F.balance - F.expected) > 0.01)
print((F.price * F.quantity).kind, (-F.delta).tag)
Output
F.debt / F.income > 0.45
abs(F.balance - F.expected) > 0.01
value neg

The arithmetic is defined by the specification so every language gets the same numbers: integers stay 64-bit (an overflow gives null with the reason int_overflow), a decimal operand is converted to a float, / always gives a float, and division by zero gives null with the reason division_by_zero, never an exception.

Constants, decimals and dates#

A constant is None, a bool, an int (64-bit), a float, a Decimal (up to 38 digits), a str, a date, or a datetime (naive, or aware with a ZoneInfo zone or a fixed offset). Python values next to a node become constants on their own; write Const(...) where no node is involved, such as Const(True) for a rule that always fires.

PythonPython binding · runs
from datetime import date, datetime
from decimal import Decimal
from zoneinfo import ZoneInfo

from cleanrules import Const

print(Const(True), Const(Decimal("0.10")).value)
print(F.signed_on >= date(2026, 1, 1))
print(F.sent_at < datetime(2026, 12, 15, 14, 0, tzinfo=ZoneInfo("Europe/Madrid")))
Output
Const(True) 0.10
F.signed_on >= datetime.date(2026, 1, 1)
F.sent_at < datetime.datetime(2026, 12, 15, 14, 0, tzinfo=zoneinfo.ZoneInfo(key='Europe/Madrid'))

Prefer Decimal for money: decimals compare exactly, so Decimal("0.1") does not equal the float 0.1 (exact comparisons). Aware datetimes compare by instant, whatever their zone; the core bundles its own time-zone database, so results do not depend on the machine. Constants that cannot be represented exactly are rejected, never rounded:

PythonPython binding · runs
from cleanrules import ExpressionError

for bad in (float("nan"), 2**64, Decimal("1" * 39)):
    try:
        Const(bad)
    except ExpressionError as err:
        print(type(bad).__name__, "->", err.message)
Output
float -> a constant cannot be NaN (nan)
int -> the integer 18446744073709551616 does not fit in 64 bits
Decimal -> the decimal Decimal('111111111111111111111111111111111111111') does not fit in 38 digits

Inspecting a tree#

Because conditions are data, you can walk them. field_paths() lists the fields a tree reads, walk() yields every node, and children() the direct ones. Since == builds a node, structural equality is same_as, and structural_key() gives a hashable key for dictionaries.

PythonPython binding · runs
cond = (F.customer.age >= 18) & F.customer.country.is_in(["ES", "PT"])
print(cond.field_paths())
print([node.tag for node in cond.walk()])
same = (F.customer.age >= 18) & F.customer.country.is_in(["PT", "ES"])
print(cond.same_as(same), cond is same)
print({cond.structural_key(): "adults"}[same.structural_key()])
Output
(('customer', 'age'), ('customer', 'country'))
['and', 'ge', 'field', 'const', 'in', 'field']
True False
adults

Nodes are immutable. Copies are the node itself, and pickling goes through the JSON format, which is the contract between versions:

PythonPython binding · runs
import copy
import pickle

clone = pickle.loads(pickle.dumps(cond))
print(clone.same_as(cond), copy.deepcopy(cond) is cond)
Output
True True

In Rust#

The Rust builder offers the same nodes. field(key) starts a path, .get(key) and .index(i) extend it; comparisons are methods; &, |, ! and the arithmetic operators are overloaded. A construction error does not interrupt the expression: it is carried along and reported by .build().

conditions.rsRust core · runs
//! Building conditions in Rust: methods for comparisons, operators for connectives.
use cleanrules::Decimal;
use cleanrules::ast::Closed;
use cleanrules::build::{constant, field};
use cleanrules::format::write_node;
use cleanrules::jiff::civil::date;
use cleanrules::json::to_string;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let adult = field("customer").get("age").ge(18) & field("country").is_in(["ES", "PT"]);
    println!("{}", to_string(&write_node(&adult.build()?)));

    let first_total = field("orders").index(0).get("total");
    let ratio = (field("debt") / field("income")).gt(0.45) | !first_total.is_null();
    println!("{}", to_string(&write_node(&ratio.build()?)));

    let window = field("age").between_closed(18, 65, Closed::Left)
        & field("signed_on").ge(date(2026, 1, 1))
        & field("rate").le(Decimal::parse("0.10")?);
    println!("{}", to_string(&write_node(&window.build()?)));

    // A construction error travels with the expression and surfaces at build().
    let bad = field("pin").matches(r"^(?=.*\d).{8,}$") & constant(true);
    match bad.build() {
        Ok(_) => println!("built"),
        Err(error) => println!("{}: {}", error.code(), error.message()),
    }
    Ok(())
}
Output
