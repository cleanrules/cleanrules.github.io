Rules and rule sets

A rule pairs a condition with what it produces, and optionally with an action to run. A rule set puts rules in order and decides how the rules that fire become one decision. This chapter covers both objects, the checks they run when you build them, and actions.

Rules#

Rule(name, when, then=None, *, priority=0, tags=(), description=None, metadata=None, do=None). Only the name and the condition are required.

PythonPython binding · runs
from decimal import Decimal

from cleanrules import F, Rule

rule = Rule(
    "vip",
    (F.customer.years > 5) & (F.order.total > 1000),
    {"discount": Decimal("0.15"), "label": "VIP", "cashback": F.order.total * 0.02},
    priority=10,
    tags=["pricing", "b2c", "pricing"],
    description="Long-standing customers with a large order",
    metadata={"owner": "pricing-team", "ticket": "PRC-142"},
)
print(rule)
print(rule.priority, rule.tags, rule.description)
print(dict(rule.metadata))
print(rule.then["cashback"], rule.then["cashback"].kind)
Output
Rule('vip', (F.customer.years > 5) & (F.order.total > 1000), {'discount': Const(Decimal('0.15')), 'label': Const('VIP'), 'cashback': F.order.total * 0.02})
10 ('b2c', 'pricing') Long-standing customers with a large order
{'owner': 'pricing-team', 'ticket': 'PRC-142'}
F.order.total * 0.02 value
name
Unique within a rule set, non-empty. It names the rule in decisions, explanations and errors.
when
The condition. The rule fires when it is true; unknown does not fire.
then
The payload: string keys mapped to constants or value expressions. F.order.total * 0.02 above is computed from the input when the rule is selected. Key order is kept and is the order of the output's keys.
priority
A 64-bit integer used by the priority hit policy; higher wins. Other policies ignore it.
tags
Labels for grouping and filtering. They are a set: duplicates are dropped and they are kept sorted, as the output shows. Summaries group rules by tag.
description, metadata
Free text and free-form data (owner, ticket, version…). Metadata must be data (no NaN, no arbitrary objects) so it can be written to JSON. Neither affects evaluation.
do
An action: a callable that RuleSet.run calls when the rule is selected (actions).

A rule without a payload is useful as a flag: its output is empty, and whether it fired is the information.

PythonPython binding · runs
flag = Rule("blocked", F.customer.blocked)
print(flag.then, flag.priority, flag.tags)
Output
{} 0 ()

When payloads are evaluated#

Payload values are evaluated only for the rules the hit policy selects (and, under any, for every rule that fired, whose payloads must be compared). A rule that fired but was not selected never fails because of its payload. A payload value that cannot be computed, such as a division by zero, is null with its reason, like any other value.

Checks when a rule is built#

Mistakes are caught when the rule is built, not when it is first evaluated, and the error names the rule:

PythonPython binding · runs
from cleanrules import RuleDefinitionError

for build in (
    lambda: Rule("", F.x > 1),
    lambda: Rule("r", F.x * 2),
    lambda: Rule("r", F.x > 1, {"flag": F.y > 2}),
    lambda: Rule("r", F.x > 1, priority=1.5),
):
    try:
        build()
    except RuleDefinitionError as err:
        print(err.code, "|", err)
Output
rule_definition_error | a rule name must be a non-empty string, got ''
rule_definition_error | the condition of "r" is a value ('mul'), not a condition
hint: compare it, for example `(a + b) > 0`
rule_definition_error | rule 'r': the payload value "flag" is a condition ('gt')
hint: payload values are constants or value expressions
rule_definition_error | rule 'r': priority must be an int, got float 1.5

Rule sets#

RuleSet(rules, *, hit_policy="first", aggregate=None, logic="boolean", strict=False). A rule set is an immutable sequence of rules: index it by position or by name, iterate it, test membership by name.

PythonPython binding · runs
from cleanrules import RuleSet

rules = RuleSet([rule, flag, Rule("loyal", F.customer.years > 2, {"discount": Decimal("0.05")})],
                hit_policy="priority")
print(len(rules), [r.name for r in rules])
print(rules["loyal"])
print(rules[0].name, "vip" in rules, rules.get("gold"))
print(rules.hit_policy, rules.aggregate, rules.logic, rules.strict)
Output
3 ['vip', 'blocked', 'loyal']
Rule('loyal', F.customer.years > 2, {'discount': Const(Decimal('0.05'))})
vip True None
priority None boolean False
hit_policy
How the rules that fired become a decision: first, priority, unique, any, rule_order or collect, as a string (any capitalization) or a HitPolicy. Hit policies
aggregate
With collect only: sum, min, max or count, applied per payload key.
logic
The logic, by name. "boolean" is Kleene's three-valued logic, the only one today; fuzzy logics with degrees of truth are planned (phase J).
strict
Raise an EvaluationError for a missing field or a type mismatch instead of making the condition unknown. Strict mode

Because a rule set is a sequence of rules, you can build a new one from an old one: RuleSet(rules, hit_policy="collect", aggregate="sum") reuses the same rules under another policy, and RuleSet([*rules, extra]) adds one.

PythonPython binding · runs
try:
    RuleSet([rule, rule])
except RuleDefinitionError as err:
    print(err)
try:
    RuleSet([rule], hit_policy="first", aggregate="sum")
except RuleDefinitionError as err:
    print(err)
Output
two rules are named "vip"
hint: rule names must be unique
an aggregate needs the collect hit policy

Immutability#

Rules, rule sets, nodes and decisions cannot be modified, so they can be shared freely, between threads too. To change a rule, build a new one.

PythonPython binding · runs
try:
    rule.priority = 3
except AttributeError as err:
    print(err)
Output
rules are immutable: cannot set 'priority'

Rules compare by identity, because their conditions are nodes, whose == builds conditions. Rules and rule sets pickle (conditions travel in the JSON format), as long as their actions do:

PythonPython binding · runs
import pickle

again = pickle.loads(pickle.dumps(rules))
print(again, again["vip"].when.same_as(rules["vip"].when), dict(again["vip"].metadata))
Output
RuleSet([vip, blocked, loyal], hit_policy='priority') True {'owner': 'pricing-team', 'ticket': 'PRC-142'}

Actions#

Conditions are data, but what a rule does is ordinary Python. Pass a callable as do. evaluate never calls it, so a decision can be computed any number of times, for explanations or what-if questions, without side effects. run evaluates and then calls the actions of the selected rules, in rule order, each with an ActionContext: the rule, the input data, the rule's result, its evaluated output and the whole decision.

PythonPython binding · runs
from cleanrules import ActionContext

sent = []


def notify(ctx: ActionContext) -> None:
    sent.append((ctx.rule.name, ctx.data["customer"]["email"], dict(ctx.output)))


promo = RuleSet([
    Rule("vip", F.customer.years > 5, {"discount": Decimal("0.15")}, do=notify),
    Rule("loyal", F.customer.years > 2, {"discount": Decimal("0.05")}, do=notify),
])
customer = {"customer": {"years": 7, "email": "ana@example.com"}}

promo.evaluate(customer)
print(sent)
decision = promo.run(customer)
print(decision, sent)
Output
[]
<Decision first: selected [vip]> [('vip', 'ana@example.com', {'discount': Decimal('0.15')})]

Under the default first policy only vip was selected, so only its action ran. If an action raises, run stops: later actions do not run, and an ActionError carries the original exception as its __cause__, the decision, and the rules whose actions had already run (executed).

PythonPython binding · runs
from cleanrules import ActionError, Const

log = []


def record(ctx: ActionContext) -> None:
    log.append(ctx.rule.name)


def mail(ctx: ActionContext) -> None:
    raise ConnectionError("mail server unreachable")


chain = RuleSet([Rule("log", Const(True), do=record), Rule("mail", Const(True), do=mail),
                 Rule("audit", Const(True), do=record)], hit_policy="rule_order")
try:
    chain.run({})
except ActionError as err:
    print(err.code, err.rule, err.executed, repr(err.__cause__))
    print(err.decision, log)
Output
action_error mail ('log',) ConnectionError('mail server unreachable')
<Decision rule_order: selected [log, mail, audit]> ['log']

An action given as code is not written to a rule file. A rule can instead name its action (Rule(..., do="notify"), or DO notify in the text syntax): the name is data, written with the rule, and the program resolves it in a mapping it supplies (actions= when loading, or rules.bind(actions)), never as an import path. An unknown name is a RegistryError before anything runs.

PythonPython binding · runs
from cleanrules import loads

promo_file = """
RULE vip IF customer.years > 5 THEN discount = DECIMAL "0.15" DO notify
RULE loyal IF customer.years > 2 THEN discount = DECIMAL "0.05" DO notify
"""
named = loads(promo_file, format="text", actions={"notify": notify})
sent.clear()
print(named.rules[0].action_name)
print(named.run(customer), sent)
Output
notify
<Decision first: selected [vip]> [('vip', 'ana@example.com', {'discount': Decimal('0.15')})]

As JSON#

A rule set is also a JSON document. Each worked example shows its rule set in that form, written by the core, for instance the loan approval rules. Python loads and saves rule files as JSON, YAML or text (Rule files).
