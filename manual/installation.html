Installation

cleanrules is pre-alpha and not on any package registry yet. Today you build it from the repository: the Python binding with maturin, the Rust crate as a path or git dependency. This page shows both, and the package names each language will use once it is published.

Requirements#

  • Rust 1.95 or later (the crate uses edition 2024), to build either the crate or the Python extension. Install it with rustup.
  • Python: CPython 3.11 or later for the binding. Free-threaded builds are supported (3.14t, and 3.15 and later with or without the GIL).
  • uv is the simplest way to build the binding; plain pip works too, because the package uses maturin as its build backend.

Python, from source#

Clone the repository and let uv build the extension into the binding's own virtual environment. uv run rebuilds it whenever the Rust sources change.

terminal
git clone https://github.com/cleanrules/cleanrules.git
cd cleanrules/bindings/python
uv run python -c "import cleanrules; print(cleanrules.__version__)"

To install it into another environment of yours, point an installer at the binding's directory. This builds a wheel with maturin and installs it:

terminal
uv pip install ./cleanrules/bindings/python      # or: pip install ./cleanrules/bindings/python

Then check what you have. Every cell in this manual ran in a session like this one:

PythonPython binding · runs
import sys

import cleanrules

print(cleanrules.__version__, cleanrules.FORMAT_VERSION)
print(sys.version)
Output
0.0.0 1
3.14.6 free-threading build (main, Jun 23 2026, 15:54:43) [Clang 22.1.3 ]

__version__ is the package version (0.0.0 until the first release) and FORMAT_VERSION is the version of the JSON format the core reads and writes. They are independent: the format has its own version, which only changes when a change to it is not additive.

Wheels and free threading#

The binding is built as three wheels per platform. CI is configured to build them for Linux (manylinux and musllinux, x86_64 and aarch64), macOS (arm64 and x86_64) and Windows (x64 and arm64). They will be published with the first release:

WheelFor
cp311-abi3CPython 3.11 to 3.14 with the GIL (the stable ABI)
cp314-cp314tfree-threaded CPython 3.14
cp315-abi3.abi3tCPython 3.15 and later, with or without the GIL (PEP 803)

The module supports free threading: importing it does not re-enable the GIL, and rule sets can be shared by threads. On builds with a GIL, evaluation releases it. See threads.

Rust, from source#

Depend on the crate by path (a local clone) or by git. The crate is named cleanrules and lives in crates/core of the repository's workspace.

Cargo.toml
[dependencies]
# a local clone of the repository
cleanrules = { path = "../cleanrules/crates/core" }
# or straight from the repository
# cleanrules = { git = "https://github.com/cleanrules/cleanrules" }

The core depends only on jiff (dates and time zones, with a bundled time-zone database), regex and thiserror, and has no unsafe code (unsafe_code = "forbid"). Every Rust program in this manual uses a path dependency like the one above. The quick start has a complete program.

Running the tests#

If you build from source, you can run the same checks the project runs:

terminal
cargo test --workspace                       # the core, its conformance vectors and property tests
cd bindings/python && uv run pytest          # the Python binding (builds the extension first)
