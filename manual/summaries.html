Summaries

A summary describes a rule set without evaluating it: its rules, every field it reads and where, the outputs it can produce, and its tags. Use it to document a rule set, to check what data it needs, or to review a change.

Summarize a rule set#

PythonPython binding · runs
from decimal import Decimal

from cleanrules import F, Rule, RuleSet

rules = RuleSet(
    [
        Rule("vip", (F.customer.years > 5) & (F.order.total > 1000),
             {"discount": Decimal("0.15"), "cashback": F.order.total * 0.02},
             priority=10, tags=["pricing"]),
        Rule("loyal", (F.customer.years > 2) | F.customer.newsletter,
             {"discount": Decimal("0.05")}, priority=5, tags=["pricing", "retention"]),
        Rule("blocked", F.customer.country.is_in(["XX", "YY"]), {"discount": 0},
             priority=99, tags=["compliance"]),
    ],
    hit_policy="priority",
)
summary = rules.summary()
summary
Output
<Summary: 3 rules, 4 fields>

Fields read#

summary.fields lists every field in order of first appearance, with the rules whose conditions read it and the (rule, key) payload values that read it. order.total below is read both by a condition and by the cashback payload:

PythonPython binding · runs
for usage in summary.fields:
    print(f"{'.'.join(usage.path):<20} conditions={usage.conditions} payloads={usage.payloads}")
Output
customer.years       conditions=('vip', 'loyal') payloads=()
order.total          conditions=('vip',) payloads=(('vip', 'cashback'),)
customer.newsletter  conditions=('loyal',) payloads=()
customer.country     conditions=('blocked',) payloads=()

This list is also what the binding reads from your data: only these paths, never the whole object (reading Python objects). The planned MCP server will derive each rule set's input schema from it (AI agents).

Rules, outputs and tags#

PythonPython binding · runs
print(summary.hit_policy, summary.logic, summary.strict)
print(summary.rules)
print(summary.outputs)
print(dict(summary.tags))
Output
priority boolean False
(RuleSummary(name='vip', priority=10, outputs=('discount', 'cashback')), RuleSummary(name='loyal', priority=5, outputs=('discount',)), RuleSummary(name='blocked', priority=99, outputs=('discount',)))
('discount', 'cashback')
{'compliance': ('blocked',), 'pricing': ('vip', 'loyal'), 'retention': ('loyal',)}

tags maps each tag to the names of its rules, tags sorted. outputs lists every payload key in order of first appearance.

As JSON#

Summary.to_dict() returns the summary document of the JSON format:

PythonPython binding · runs
import json

doc = summary.to_dict()
print(list(doc), list(doc["summary"]))
print(json.dumps(doc["summary"]["fields"][1]))
Output
['version', 'summary'] ['hit_policy', 'logic', 'rules', 'fields', 'outputs', 'tags']
{"path": ["order", "total"], "conditions": ["vip"], "payloads": [{"rule": "vip", "key": "cashback"}]}

The agent guardrail example uses a summary to list what a tool call must provide. Static audit (unsatisfiable conditions, shadowed rules, overlaps, gaps) is planned for phase J.

A text rendering#

str() of a summary is its text rendering, written by the core in the rule syntax, the same in every language:

PythonPython binding · runs
print(summary)
Output
Rule set: 3 rules, hit policy priority, logic boolean
  priority  name     condition                                  outputs
        10  vip      customer.years > 5 AND order.total > 1000  discount, cashback
         5  loyal    customer.years > 2 OR customer.newsletter  discount
        99  blocked  customer.country IN ("XX", "YY")           discount
Fields read (4):
  customer.years       conditions of vip, loyal
  order.total          conditions of vip; payloads of vip (cashback)
  customer.newsletter  conditions of loyal
  customer.country     conditions of blocked
Outputs: discount, cashback
Tags: compliance (blocked); pricing (vip, loyal); retention (loyal)
