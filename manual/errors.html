Manual / Chapter 10

Errors

Every error has a stable code, the same in every language, a message written by the core that names the rule or node and says how to fix it, and a fixed set of context fields. Each language presents them idiomatically: exceptions in Python, Java, Scala, C++ and JavaScript, values in Rust and Go, status codes in C, tuples in Erlang.

Catching errors in Python#

Every exception derives from CleanRulesError, so one except catches them all. str(err) is the message, with the rule and a hint: line when there is something useful to say:

PythonPython binding · runs
from cleanrules import CleanRulesError, F, Rule, RuleSet

rules = RuleSet([Rule("a", F.x > 1, {"v": 1}), Rule("b", F.x > 0, {"v": 2})], hit_policy="unique")
try:
    rules.evaluate({"x": 5})
except CleanRulesError as err:
    print(type(err).__name__, "|", err.code, "|", err.rules)
    print(str(err))
Output
HitPolicyError | hit_policy_error | ('a', 'b')
2 rules fired under the unique hit policy
hint: make the conditions mutually exclusive, or use first or priority

The hierarchy#

In Python, the classes keep familiar builtin bases, so existing except clauses keep working: an ExpressionError is also a TypeError and a ValueError, a RuleNotFoundError a KeyError, and so on.

PythonPython binding · runs
import cleanrules

for name in ("MissingFieldError", "TypeMismatchError", "HitPolicyError", "ExpressionError",

    cls = getattr(cleanrules, name)
    bases = [b.__name__ for b in cls.__mro__[1:] if b not in (object, BaseException, Exception)]
    print(f"{name:<20} {cls.default_code:<22} {bases}")

In Python every context field is an attribute of the exception (None or empty when it does not apply), with paths as tuples:

PythonPython binding · runs
from cleanrules import RegistryError

try:
    RuleSet([Rule("a", F.x > 1)], logic="lukasiewicz")
except RegistryError as err:
    print(err.code, err.name, err.available)
    print(err.hint)
Output
registry_error lukasiewicz ('boolean',)
this version of the core has the logic "boolean"

Errors also carry node: the operand that broke a construction rule, or the innermost node whose evaluation failed (the field, when it is missing). In Python it is an Expr, and the message ends with it (…, in `F.customer.age`). unsupported errors carry operation and reason, and an ActionError carries the decision whose actions were running (actions). Errors pickle with their attributes, so they cross process boundaries:

PythonPython binding · runs
import pickle

strict = RuleSet([Rule("adult", F.age >= 18)], strict=True)
try:
    strict.evaluate_many([{"age": 20}, {}])
except CleanRulesError as err:
    again = pickle.loads(pickle.dumps(err))
    print(type(again).__name__, again.code, again.rule, again.path, again.row)
Output
MissingFieldError missing_field adult ('age',) 1

errors.rsRust core · runs
//! Errors in Rust: one Error type with a stable code, a hierarchy and context.
use cleanrules::build::field;
use cleanrules::format::{ValueContext, read_value};
use cleanrules::json::{Limits, parse};
use cleanrules::rules::{Config, Rule, RuleSet};
use cleanrules::{Error, ErrorCode};

fn main() -> Result<(), Error> {
    let adult = Rule::new("adult", field("customer").get("age").ge(18).build()?)?;
    let strict = RuleSet::new(
        vec![adult],
        Config {
            strict: true,
            ..Config::default()
        },
    )?;

    let data = read_value(
        &parse(r#"{"customer": {"name": "Ana"}}"#, &Limits::default())?,
        "",
        ValueContext::Data,
    )?;
    match strict.evaluate(&data) {
        Ok(decision) => println!("fired: {}", decision.results()[0].fired),
        Err(error) if error.code().is_a(ErrorCode::EvaluationError) => {
            let context = error.context();
            println!("code:    {}", error.code());
            println!("parent:  {:?}", error.code().parent());
            println!("rule:    {:?}", context.rule);
            println!("path:    {:?}", context.path);
            println!("message: {error}");
        }
        Err(error) => return Err(error),
    }
    Ok(())
}

errors.cC ABI · runs
#include <stdio.h>
#include <string.h>
#include <cleanrules.h>

int main(void) {
    const char *text = "STRICT\n\nRULE adult IF customer.age >= 18";
    const char *input = "{\"customer\": {\"name\": \"Ana\"}}";
    cr_error *error = NULL;
    cr_ruleset *adult = NULL;
    cr_decision *decision = NULL;
    if (cr_ruleset_read(text, strlen(text), CR_FORMAT_TEXT, NULL, &adult, &error) == CR_OK) {
        cr_ruleset_evaluate(adult, input, strlen(input), NULL, &decision, &error);
    }
    if (error != NULL) {
        cr_status code = cr_error_code(error);
        printf("code:    %s\n", cr_status_name(code));
        printf("parent:  %s\n", cr_status_name(cr_error_parent(code)));
        printf("message: %s\n", cr_error_message(error));
        printf("json:    %s\n", cr_error_json(error));
        if (cr_error_is(code, CR_EVALUATION_ERROR)) {
            /* missing_field, type_mismatch or hit_policy_error: handle the input */
        }
    }
    cr_error_free(error);
    cr_decision_free(decision);
    cr_ruleset_free(adult);
    return 0;
}

Which error comes first#

  • Strict evaluation: every condition first, in rule order, each depth-first and left to right; then the payloads needed by the policy; a hit-policy error last (except unique, which raises as soon as a second rule fires).
  • Batches: the first failing input, in order; its position is row.
  • Reading a document: size, nesting and syntax; then version; then the shape; then the construction rules (format errors).
