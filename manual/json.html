Rules as JSON

Rules, decisions and explanations have one JSON form, defined by the format specification and written by the core. It is the contract between languages and with your files: a rule written in one language and read in another is the same tree and decides the same way.

Documents#

A document is an object with a version and exactly one content key:

ContentThe core reads itThe core writes itFrom Python today
conditionyesyesnodes pickle through it
rule, rulesetyesyesloading and saving rule files is task D.1
decisionyes, checked against its rule setyesdecision.to_dict()
explanationno (output only)yesexplanation.to_dict()
summaryno (output only)yessummary.to_dict()

Values that JSON cannot carry exactly have their own encoding: {"$decimal": "0.15"}, {"$date": "2026-12-31"}, {"$datetime": "2026-12-15T14:00:00+01:00[Europe/Madrid]"}, {"$float": "inf"}, and {"$int": "…"} for integers beyond 253. The format reference has the full table.

Writing a decision from Python#

A decision document records every rule's result tree, with the value read at each field and the truth at each condition, and the rules selected. Outputs are not stored: they are derived from the payload trees.

PythonPython binding · runs
import json

from cleanrules import F, Rule, RuleSet

rules = RuleSet([Rule("vip", (F.customer.years > 5) & (F.order.total > 1000), {"discount": 0.15})])
decision = rules.evaluate({"customer": {"years": 7}, "order": {"total": 1500}})
print(json.dumps(decision.to_dict(), indent=1))

Reading documents in Rust#

The core reads rule set documents today. This program reads one, evaluates it, writes the decision as a document, and reads that back. Reading a decision checks it against the rule set node by node, so a tampered decision (here, a constant changed from 5 to 2) is rejected with a pointer to the node. A document of a newer format version is rejected too.

jsonfmt.rsRust core · runs
//! Rules as JSON: read a rule set document, evaluate, write the decision and read it back.
use cleanrules::format::{
    Document, ValueContext, read_decision_document, read_document, read_value, write_decision,
};
use cleanrules::json::{Json, Limits, parse, to_string};

const RULES: &str = r#"{
  "version": 1,
  "ruleset": {
    "hit_policy": "first",
    "rules": [
      {"name": "vip",
       "when": {"op": "and", "operands": [
         {"op": "gt", "left": {"op": "field", "path": ["customer", "years"]},
                      "right": {"op": "const", "value": 5}},
         {"op": "gt", "left": {"op": "field", "path": ["order", "total"]},
                      "right": {"op": "const", "value": 1000}}]},
       "then": {"discount": {"op": "const", "value": {"$decimal": "0.15"}}}}
    ]
  }
}"#;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let limits = Limits::default();
    let Document::RuleSet(rules) = read_document(RULES, &limits)? else {
        return Err("not a rule set document".into());
    };
    let input = r#"{"customer": {"years": 7}, "order": {"total": 1500}}"#;
    let data = read_value(&parse(input, &limits)?, "", ValueContext::Data)?;
    let decision = rules.evaluate(&data)?;

    let document = Json::Object(vec![
        ("version".to_owned(), parse("1", &limits)?),
        ("decision".to_owned(), write_decision(&decision)),
    ]);
    let text = to_string(&document);
    println!("decision document: {} bytes", text.len());

    // Reading it back checks it against the rule set, node by node.
    let again = read_decision_document(&text, &rules, &limits)?;
    println!(
        "read back, selected: {:?}",
        again.selected().map(|r| r.rule.name()).collect::<Vec<_>>()
    );

    let tampered = text.replace(r#""value":5"#, r#""value":2"#);
    match read_decision_document(&tampered, &rules, &limits) {
        Ok(_) => println!("accepted"),
        Err(error) => println!("{} at {:?}", error.code(), error.context().pointer),
    }

    let newer = RULES.replacen("\"version\": 1", "\"version\": 2", 1);
    if let Err(error) = read_document(&newer, &limits) {
        println!("{}: {}", error.code(), error.message());
    }
    Ok(())
}
Output
decision document: 468 bytes
read back, selected: ["vip"]
decision_mismatch at Some("/decision/results/0/when/children/0/children/1/value")
unsupported_version: this reader knows format version 1

Versioning#

  • The format version (1) is independent of the package versions. It changes only for a change that is not additive, and readers reject versions they do not know (unsupported_version).
  • Readers are strict: unknown keys, duplicate keys, integers beyond 64 bits and invalid nodes are errors with a JSON Pointer, never silently ignored.
  • Writers are canonical: the same object is always written the same way (in values sorted, defaults omitted), so documents can be compared and diffed.
  • Member order matters in one place: a payload's keys, which are the order of the output.
  • Readers enforce limits on size, JSON nesting and node depth, so documents from untrusted sources are safe to read.

Planned#

Loading and saving rule files in JSON and YAML from every binding (D.1), a text DSL with its own parser (IF … THEN …, D.2) and decision tables from rows, CSV or JSON (D.3). Until D.1, Python builds rule sets in code, as every example in this manual does.
