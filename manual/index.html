Manual / Chapter 01

The cleanrules manual

cleanrules is a rules engine whose conditions are data. You write a rule once, the Rust core evaluates it, and every decision comes with an explanation: which rules fired, which did not, why, and how far each input was from changing the outcome. This manual teaches you to use it, from installation to the API reference.

Everything on these pages ran. The Python cells were executed with the Python binding built from source, the Rust programs with the core crate (crates/core), the C programs with the C ABI (crates/ffi), the C++ programs with cleanrules.hpp and the TypeScript programs with the JavaScript binding (bindings/js); the output under each one is what it printed. Nothing is published to a package registry yet, and the bindings for Java, Scala, Go and Erlang are planned: where this site shows them, it says so.

At a glance#

Two rules, one input. F.customer.years > 5 does not compare anything in Python: it builds a node of a condition tree, which the core evaluates later. That is why the engine can tell you afterwards that vip missed by 2 years.

PythonPython binding · runs
from cleanrules import F, Rule, RuleSet

rules = RuleSet([
    Rule("vip", (F.customer.years > 5) & (F.order.total > 1000), {"discount": 0.15}),
    Rule("loyal", F.customer.years > 2, {"discount": 0.05}),
])

decision = rules.evaluate({"customer": {"years": 3}, "order": {"total": 1500}})
print(dict(decision.output))

why = decision.why_not("vip")
cause = why.causes[0]
print(why.status, "because", cause.node, "is", cause.truth, "- short by", cause.counterfactual.gap)
Output
{'discount': 0.05}
not_fired because F.customer.years > 5 is false - short by 2

The rule set used the default hit policy, first: the first rule that fires wins, and loyal was the only one that did. The rest of the manual explains each piece of this example in turn.

The concepts in one page#

Condition
A tree of nodes built with F (fields), constants, comparisons, &, |, ~ and methods such as is_in or between. It is data, never a Python function, so it can be explained, written to JSON, read in another language and audited. Writing conditions
Rule
A unique name, a condition (when) and an optional payload (then): string keys mapped to constants or value expressions such as F.total * 0.1. A rule also has a priority, tags, a description, metadata, and optionally an action (do), plain Python that run calls when the rule is selected. Rules and rule sets
Rule set
Rules in order, plus a hit policy that turns the rules that fired into a decision (first, priority, unique, any, rule_order, collect), an optional aggregate for collect, a logic, and a strict flag. Hit policies
Three-valued logic
A condition is true, false or unknown. Missing data, nulls and values of the wrong type make it unknown, with a structured reason; a rule fires only when its condition is true. Strict mode raises an error instead. Evaluating data
Decision
The result of evaluating a rule set on one input: every rule's result, the rules the policy selected, and their outputs. Evaluating data
Explanation
Each rule's status (selected, fired, not_fired, unknown), the conditions it needed, the values it read, and counterfactuals such as "short by 2". Explanations
Summary
What a rule set reads and produces, computed without evaluating it. Summaries
JSON format v1
The versioned contract between languages: conditions, rules, rule sets, decisions, explanations and summaries as JSON documents. Rules as JSON

How to read this manual#

  • Python cells run in order, in one Python session per page, like a notebook: a later cell can use a name defined earlier on the same page. The output under a cell is what it printed, followed by the value of its last line when that line is an expression, as the Python REPL shows it.
  • The cells ran on CPython 3.14.6, a free-threaded build, with the binding at version 0.0.0 (pre-alpha). The binding supports CPython 3.11 and later.
  • Rust programs are complete and depend on the core by path; the output is what they printed.
  • TypeScript programs ran with Node 26, which strips the types (they were type-checked with tsc), on the native addon; C++ programs were compiled as C++17 with Apple clang against the installed CMake package. The output is what they printed.
  • Windows carry a badge: Python binding · runs, Rust core · runs, JavaScript binding · runs, C++ binding · runs, written by the core, or design preview for planned APIs.
