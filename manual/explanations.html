Explanations and counterfactuals

Every decision can explain itself. For each rule, the explanation says what happened to it, which conditions mattered, the values they read, and for the conditions that went the wrong way, what the input would have needed. It is built from the decision alone: nothing is evaluated again.

The structure#

decision.explain() returns an Explanation: one RuleExplanation per rule, in rule order. Each has:

status
selected (fired and chosen by the hit policy), fired (fired but not chosen), not_fired (its condition was false) or unknown (its condition was unknown).
requirement
What decided the outcome: a single Cause, or a CauseGroup whose kind is "all" (every item matters) or "any" (one item is enough). causes flattens it.
note
For a rule that fired but lost: the winner and why (notes).
achievable
For a rule that did not fire: whether changing the listed conditions can make it fire.

A Cause is one elementary condition (a comparison, a membership test…) with its truth, whether it is negated (it sits under a ~, so the rule needs it false), whether it holds (went the way the rule needed), the values it read, a reason when it is unknown, and a counterfactual when it did not hold.

Here is a rule set with three different shapes of condition, and an applicant who is 16:

PythonPython binding · runs
from cleanrules import F, Rule, RuleSet

rules = RuleSet(
    [
        Rule("fast_track", (F.score >= 750) | (F.income > 100_000), {"lane": "fast"}),
        Rule("eligible", ~(F.country.is_in(["IR", "KP"]) | (F.age < 18)), {"lane": "standard"}),
        Rule("review", F.score.between(600, 700), {"lane": "review"}),
    ],
    hit_policy="first",
)
decision = rules.evaluate({"score": 700, "income": 80_000.0, "country": "ES", "age": 16})
explanation = decision.explain()
explanation
Output
<Explanation: fast_track: not_fired, eligible: not_fired, review: selected>

"Any of these": one change is enough#

fast_track needs a high score or a high income. It did not fire, and its requirement is an any group: changing either condition would do. The gaps say by how much each one missed.

PythonPython binding · runs
fast = explanation.for_rule("fast_track")
print(fast.status, fast.achievable, fast.requirement.kind)
for cause in fast.causes:
    print(" ", cause.node, cause.truth, "gap:", cause.counterfactual.gap)
Output
not_fired True any
  F.score >= 750 false gap: 50
  F.income > 100000 false gap: 20000.0

Negated conditions#

eligible is ~(sanctioned country | under 18). The explanation pushes the negation inward (De Morgan) and lists only the conditions that went the wrong way: F.age < 18 is true, but the rule needs it false. The counterfactual is the comparison the field must satisfy, already negated: age >= 18, 2 years away.

PythonPython binding · runs
eligible = explanation.for_rule("eligible")
print(eligible.status, eligible.requirement)
for cause in eligible.causes:
    print(f"  {cause.node!r:<34} truth={cause.truth:<5} negated={cause.negated!s:<5} holds={cause.holds}")
    if cause.counterfactual:
        print("    needs", cause.counterfactual)
Output
not_fired <Cause F.age < 18: true>
  F.age < 18                         truth=true  negated=True  holds=False
    needs Counterfactual(path=('age',), op='ge', target=18, gap=2)

Selected rules#

For a rule that fired, the requirement lists the conditions that made it fire, each of them true. A between is reported as its two halves:

PythonPython binding · runs
review = explanation.for_rule("review")
print(review.status, [(str(c.node), c.values) for c in review.causes])
Output
selected [('F.score >= 600', ((('score',), 700),)), ('F.score <= 700', ((('score',), 700),))]

Counterfactuals and gaps#

A counterfactual is given for a cause that did not hold and is not unknown, when the cause compares one field with one constant. It records the field's path, the comparison it needs (op), the target and the gap. The gap's type follows the values:

PythonPython binding · runs
from datetime import date, datetime
from decimal import Decimal
from zoneinfo import ZoneInfo

madrid = ZoneInfo("Europe/Madrid")
gaps = RuleSet([
    Rule("balance", F.balance >= Decimal("1000.00")),
    Rule("renewal", F.contract_end <= date(2026, 12, 31)),
    Rule("on_time", F.sent_at <= datetime(2026, 10, 25, 1, 0, tzinfo=madrid)),
    Rule("limit", F.amount < 500),
], hit_policy="rule_order")
d = gaps.evaluate({"balance": Decimal("950.50"), "contract_end": date(2027, 1, 15),
                   "sent_at": datetime(2026, 10, 25, 4, 0, tzinfo=madrid), "amount": 500})
for entry in d.explain().rules:
    print(f"{entry.rule:<8} {entry.causes[0].counterfactual.gap!r}")
Output
balance  Decimal('49.50')
renewal  datetime.timedelta(days=15)
on_time  datetime.timedelta(seconds=14400)
limit    0
  • Numbers: the exact difference. Two decimals give a Decimal with the larger scale (49.50); a decimal and a float give no gap, since the difference would not be exact.
  • Dates: a timedelta of whole days.
  • Datetimes: a timedelta. Aware datetimes subtract instants, so the gap above is 4 hours across the night when clocks went back in Madrid (01:00 to 04:00 on 25 October 2026), not 3.
  • At the limit: a gap of 0 means a strict comparison failed exactly at its bound (500 < 500).
  • == and != have no distance: a counterfactual without a gap is given only for a negated cause.

The eligibility example uses day and hour gaps to tell an applicant exactly what is missing.

When a rule cannot fire#

Each way to make a rule fire is checked against the decision before it is listed. When the conditions conflict, the explanation says so with achievable=False:

PythonPython binding · runs
odd = RuleSet([Rule("never", (F.x > 1) & ~(F.x > 1))])
never = odd.evaluate({"x": 8}).why_not("never")
print(never.status, never.achievable)
for cause in never.causes:
    print(" ", cause.node, cause.truth, "negated" if cause.negated else "", cause.counterfactual)
Output
not_fired False
  F.x > 1 true negated Counterfactual(path=('x',), op='le', target=1, gap=7)

Notes#

Rules that fired but lost carry a note with the winner and, under priority, both priorities:

PythonPython binding · runs
from cleanrules import Note

tiers = RuleSet([
    Rule("loyal", F.years > 2, {"pct": 10}, priority=5),
    Rule("vip", F.years > 5, {"pct": 15}, priority=10),
    Rule("partner", F.years > 5, {"pct": 15}, priority=10),
], hit_policy="priority")
for entry in tiers.evaluate({"years": 7}).explain().rules:
    print(entry.rule, entry.status, entry.note)
Output
loyal fired Note(kind='lower_priority', winner='vip', priority=5, winner_priority=10)
vip selected None
partner fired Note(kind='same_priority', winner='vip', priority=10, winner_priority=10)

Unknown rules#

For an unknown rule, the causes that are unknown carry their reasons. Here the score is missing: fast_track is unknown, because income alone did not decide it, while eligible is decided without the score.

PythonPython binding · runs
d = rules.evaluate({"income": 80_000.0, "country": "ES", "age": 30})
for entry in d.explain().rules:
    reasons = [c.reason.code for c in entry.causes if c.reason]
    print(entry.rule, entry.status, reasons)
Output
fast_track unknown ['missing_field']
eligible selected []
review unknown ['missing_field', 'missing_field']

The JSON form#

Explanation.to_dict() returns the explanation document of the JSON format. Groups are written as {"all": [...]} or {"any": [...]}, and each cause has an at pointer into the decision document, so a viewer can highlight the exact node:

PythonPython binding · runs
doc = decision.explain().to_dict()
entry = doc["explanation"]["rules"][0]
print(entry["status"], list(entry["requirement"]))
first = entry["requirement"]["any"][0]
print(first["at"], first["counterfactual"])
Output
not_fired ['any']
/decision/results/0/when/children/0 {'path': ['score'], 'op': 'ge', 'target': 750, 'gap': 50}
PythonPython binding · runs
decision_doc = decision.to_dict()
node = decision_doc
for part in first["at"].strip("/").split("/"):
    node = node[int(part)] if isinstance(node, list) else node[part]
print(node["op"], node["truth"])
Output
ge False

Every worked example shows its explanation in this form, written by the core, next to the Python objects. The concepts guide covers how requirements are built and simplified, as the specification defines it.

A text rendering#

str() of an explanation is its text rendering, generated by the core so it reads the same in every language, with conditions written in the rule syntax:

PythonPython binding · runs
print(explanation)
Output
HIT POLICY first: selected review
[ ] fast_track (not fired): score >= 750 OR income > 100000
    would fire if any of these changed:
    - score >= 750 is false (score = 700); short by 50
    - income > 100000 is false (income = 80000e0); short by 20000
[ ] eligible (not fired): NOT (country IN ("IR", "KP") OR age < 18)
    - age < 18 is true (age = 16), but the rule needs it false; needs age >= 18 (short by 2)
[x] review (selected): score BETWEEN 600 AND 700
    because all of these hold:
    - score >= 600 is true (score = 700)
    - score <= 700 is true (score = 700)
