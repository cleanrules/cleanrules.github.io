Loan approval

A lender screens applicants with six rules. Some are hard stops (sanctions, age) that must win whatever else fires; others grant an approval with an interest rate; a fallback refers everything else to a person.

The problem

Loan approval, in words.

The rules, in words:

  • sanctioned: an applicant from a sanctioned country is declined (priority 100);
  • underage: under 18 is declined (90);
  • over_indebted: debt above 45 % of income is referred to a person (50);
  • prime: a score of 740 or more and an income of at least 40,000 is approved at 6.9 % APR (20);
  • near_prime: a score from 660 up to (not including) 740 and an income of at least 30,000 is approved at 9.9 % (10);
  • fallback: anything else is referred (0).

Several rules can fire at once: an over-indebted applicant may also qualify as prime. The priority hit policy settles it: the rule that fired with the highest priority wins, so the order in which rules are written does not matter, and a hard stop always beats an approval.

input.json
{"age": 34, "country": "ES", "score": 728, "income": 52000, "debt": 14000}

One applicant: 34 years old, from Spain, a score of 728, an income of 52,000 and a debt of 14,000. The input in the JSON format, where decimals and dates have their own encoding; in Python it is the dict in the program below.

loan.rsRust core · runs
//! Loan approval: the PRIORITY hit policy.
use cleanrules::ast::Closed;
use cleanrules::build::{Build, constant, field};
use cleanrules::explain::{Cause, Gap, Requirement, explain};
use cleanrules::format::{ValueContext, read_value, write_path, write_value};
use cleanrules::json::{Limits, parse, to_string};
use cleanrules::rules::{Config, HitPolicy, Rule, RuleSet};
use cleanrules::{Decimal, Value};

type Result<T> = std::result::Result<T, Box<dyn std::error::Error>>;

fn rule(name: &str, when: Build, then: Vec<(&str, Build)>, priority: i64) -> Result<Rule> {
    let then = then
        .into_iter()
        .map(|(key, value)| Ok((key.to_owned(), value.build()?)))
        .collect::<Result<Vec<_>>>()?;
    Ok(Rule::with_payload(name, when.build()?, then)?.priority(priority))
}

fn rules() -> Result<RuleSet> {
    let decide = |what: &str| vec![("decision", constant(what))];
    let approve = |apr: Decimal| vec![("decision", constant("approve")), ("apr", constant(apr))];
    let rules = vec![
        rule(
            "sanctioned",
            field("country").is_in(["IR", "KP", "SY"]),
            decide("decline"),
            100,
        )?,
        rule("underage", field("age").lt(18), decide("decline"), 90)?,
        rule(
            "over_indebted",
            (field("debt") / field("income")).gt(0.45),
            decide("refer"),
            50,
        )?,
        rule(
            "prime",
            field("score").ge(740) & field("income").ge(40_000),
            approve(Decimal::parse("6.9")?),
            20,
        )?,
        rule(
            "near_prime",
            field("score").between_closed(660, 740, Closed::Left) & field("income").ge(30_000),
            approve(Decimal::parse("9.9")?),
            10,
        )?,
        rule("fallback", constant(true), decide("refer"), 0)?,
    ];
    let config = Config {
        hit_policy: HitPolicy::Priority,
        ..Config::default()
    };
    Ok(RuleSet::new(rules, config)?)
}

fn input(json: &str) -> Result<Value> {
    Ok(read_value(
        &parse(json, &Limits::default())?,
        "",
        ValueContext::Data,
    )?)
}

fn causes<'r, 'd, 'a>(requirement: &'r Requirement<'d, 'a>) -> Vec<&'r Cause<'d, 'a>> {
    match requirement {
        Requirement::Cause(cause) => vec![cause],
        Requirement::Group(_, items) => items.iter().flat_map(|item| causes(item)).collect(),
    }
}

fn main() -> Result<()> {
    let rules = rules()?;
    let applicant =
        input(r#"{"age": 34, "country": "ES", "score": 728, "income": 52000, "debt": 14000}"#)?;
    let decision = rules.evaluate(&applicant)?;

    let selected: Vec<&str> = decision.selected().map(|r| r.rule.name()).collect();
    println!("selected: {selected:?}");
    if let Some(output) = decision.output()? {
        println!("output:   {}", to_string(&write_value(&output)));
    }

    let explanation = explain(&decision);
    for entry in &explanation.rules {
        println!("{:<14} {}", entry.rule, entry.status.as_str());
    }
    let prime = explanation
        .rules
        .iter()
        .find(|e| e.rule == "prime")
        .ok_or("no rule prime")?;
    for cause in causes(&prime.requirement) {
        if let Some(cf) = &cause.counterfactual {
            let gap = match &cf.gap {
                Some(Gap::Number(n)) => to_string(&write_value(n)),
                other => format!("{other:?}"),
            };
            println!(
                "prime needs {} {} {}: gap {gap}",
                to_string(&write_path(&cf.path)),
                cf.op.tag(),
                to_string(&write_value(&cf.target))
            );
        }
    }
    Ok(())
}

// Design preview: the Java binding does not exist yet (phase G).
import io.github.cleanrules.*;
import java.math.BigDecimal;

import static io.github.cleanrules.Conditions.*;

public class Loan {
    record Applicant(int age, String country, int score, int income, int debt) {}

    public static void main(String[] args) {
        var rules = RuleSet.builder()
            .hitPolicy(HitPolicy.PRIORITY)
            .add(Rule.named("sanctioned").when(field("country").isIn("IR", "KP", "SY"))
                .then("decision", "decline").priority(100))
            .add(Rule.named("underage").when(field("age").lt(18))
                .then("decision", "decline").priority(90))
            .add(Rule.named("over_indebted").when(field("debt").div(field("income")).gt(0.45))
                .then("decision", "refer").priority(50))
            .add(Rule.named("prime").when(field("score").ge(740).and(field("income").ge(40_000)))
                .then("decision", "approve").then("apr", new BigDecimal("6.9")).priority(20))
            .add(Rule.named("near_prime")
                .when(field("score").between(660, 740, Closed.LEFT).and(field("income").ge(30_000)))
                .then("decision", "approve").then("apr", new BigDecimal("9.9")).priority(10))
            .add(Rule.named("fallback").when(constant(true)).then("decision", "refer"))
            .build();

        var decision = rules.evaluate(new Applicant(34, "ES", 728, 52_000, 14_000));
        System.out.println(decision.fired());
        System.out.println(decision.output().orElseThrow());
    }
}

// Design preview: the Go binding does not exist yet (phase H).
package main

import (
	"fmt"
	"log"

	cr "github.com/cleanrules/cleanrules/bindings/go"
)

type Applicant struct {
	Age     int    `json:"age"`
	Country string `json:"country"`
	Score   int    `json:"score"`
	Income  int    `json:"income"`
	Debt    int    `json:"debt"`
}

func main() {
	rules, err := cr.NewRuleSet([]*cr.Rule{
		cr.NewRule("sanctioned", cr.Field("country").In("IR", "KP", "SY")).
			Then("decision", "decline").Priority(100),
		cr.NewRule("underage", cr.Field("age").Lt(18)).Then("decision", "decline").Priority(90),
		cr.NewRule("over_indebted", cr.Field("debt").Div(cr.Field("income")).Gt(0.45)).
			Then("decision", "refer").Priority(50),
		cr.NewRule("prime", cr.And(cr.Field("score").Ge(740), cr.Field("income").Ge(40000))).
			Then("decision", "approve").Then("apr", cr.MustDecimal("6.9")).Priority(20),
		cr.NewRule("near_prime", cr.And(
			cr.Field("score").BetweenClosed(660, 740, cr.Left),
			cr.Field("income").Ge(30000),
		)).Then("decision", "approve").Then("apr", cr.MustDecimal("9.9")).Priority(10),
		cr.NewRule("fallback", cr.Const(true)).Then("decision", "refer"),
	}, cr.WithHitPolicy(cr.Priority))
	if err != nil {
		log.Fatal(err)
	}

	decision, err := rules.Evaluate(Applicant{Age: 34, Country: "ES", Score: 728, Income: 52000, Debt: 14000})
	if err != nil {
		log.Fatal(err)
	}
	output, err := decision.Output()
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(decision.Fired())
	fmt.Println(output)
}

/* A whole file, or NULL. */
static char *read_file(const char *path, size_t *len) {
    FILE *file = fopen(path, "rb");
    char *text = NULL;
    if (file != NULL && fseek(file, 0, SEEK_END) == 0) {
        long size = ftell(file);
        if (size >= 0 && fseek(file, 0, SEEK_SET) == 0 && (text = malloc((size_t)size + 1)) != NULL) {
            *len = fread(text, 1, (size_t)size, file);
        }
    }
    if (file != NULL) fclose(file);
    return text;
}

static int fail(cr_error *error) {
    fprintf(stderr, "%s: %s\n", cr_status_name(cr_error_code(error)), cr_error_message(error));
    cr_error_free(error);
    return 1;
}

int main(void) {
    /* The rule set document shown in the JSON tab. */
    size_t len = 0;
    char *text = read_file("loan.ruleset.json", &len);
    if (text == NULL) {
        perror("loan.ruleset.json");
        return 1;
    }
    cr_error *error = NULL;
    cr_ruleset *rules = NULL;
    cr_status status = cr_ruleset_read(text, len, CR_FORMAT_JSON, NULL, &rules, &error);
    free(text);
    if (status != CR_OK) return fail(error);

    const char *applicant =
        "{\"age\": 34, \"country\": \"ES\", \"score\": 728, "
        "\"income\": 52000, \"debt\": 14000}";
    cr_decision *decision = NULL;
    char *output = NULL;
    if (cr_ruleset_evaluate(rules, applicant, strlen(applicant), NULL, &decision, &error) == CR_OK &&
        cr_decision_output(decision, &output, NULL, &error) == CR_OK) {
        puts(output);  /* a JSON object, or null */
    }
    cr_string_free(output);
    cr_decision_free(decision);
    cr_ruleset_free(rules);
    return error == NULL ? 0 : fail(error);
}

What the engine decided.

The decision document records every rule's result tree, with each value read; its outputs are derived from it. It equals decision.to_dict() in Python.

The explanation

Why, and why not.

The explanation answers the applicant's obvious question, "why not prime?": the score of 728 is 12 points short of 740, and nothing else was missing (the income condition held). achievable is True: raising the score alone would make prime fire. The note on fallback says why it lost.

print("prime is", why.status, "- achievable:", why.achievable)
for cause in why.causes:
    print(" ", cause.node, "is", cause.truth, dict(cause.values), cause.counterfactual)

What happens if…

Change the input, see the outcome move.

More debt. With a debt of 30,000 the ratio is 0.58, so over_indebted fires. near_prime still fires too, but priority 50 beats 10, and the applicant is referred.

No score. Without a score, prime and near_prime are unknown, not false, and neither fires: cleanrules never approves on missing data. The fallback refers the applicant, and the explanation says exactly which field was missing.

Python · continues the programPython binding · runs
more_debt = {**applicant, "debt": 30_000}
no_score = {"age": 34, "country": "ES", "income": 52_000, "debt": 14_000}

for data in (more_debt, no_score):
    d = rules.evaluate(data)
    print(d, dict(d.output))
    for rule in d.explain().rules:
        if rule.status == "unknown":
            print("  unknown:", rule.rule, "-", rule.causes[0].reason)
