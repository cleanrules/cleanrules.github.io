Order validation

An order service validates incoming orders. Each rule describes a problem; the problems found are the outputs. The record below is messy on purpose: an email is missing and a quantity arrived as a string.

The problem

Order validation, in words.

  • missing_email: the customer has no email (is_null);
  • bad_email: the email does not look like an address (a negated matches);
  • bad_quantity: the quantity is zero or negative;
  • total_mismatch: the total differs from quantity × unit price by more than 0.01 (abs of an expression);
  • ships_before_order: the ship date is before the order date (two date fields).
input.json
{
  "customer": {"name": "Ana"},
  "quantity": "3",
  "unit_price": 19.99,
  "total": 59.97,
  "order_date": {"$date": "2026-10-30"},
  "ship_date": {"$date": "2026-10-28"}
}

A customer without an email, a quantity of "3" (a string), a unit price of 19.99, a total of 59.97, ordered on 30 October and shipped on 28 October. The input in the JSON format, where decimals and dates have their own encoding; in Python it is the dict in the program below.

The rules in every language

One rule set, ten ways to write it.

Python, Rust, TypeScript, C and C++ run today, built from the repository, and the JSON tab is the rule set document the core writes. Java, Scala, Go and Erlang are design previews of the planned bindings: they show the intended API, and the result they would print is the one the core computes for the same rules and data.

orders.rsRust core · runs
//! Order validation: unknown is not "passed", and strict mode raises.
use cleanrules::Value;
use cleanrules::build::{Build, constant, field};
use cleanrules::explain::{Requirement, Status, explain};
use cleanrules::format::{ValueContext, read_value, write_path};
use cleanrules::json::{Limits, parse, to_string};
use cleanrules::rules::{Config, HitPolicy, Rule, RuleSet};

type Result<T> = std::result::Result<T, Box<dyn std::error::Error>>;

fn rule(name: &str, when: Build, then: Vec<(&str, Build)>) -> Result<Rule> {
    let then = then
        .into_iter()
        .map(|(key, value)| Ok((key.to_owned(), value.build()?)))
        .collect::<Result<Vec<_>>>()?;
    Ok(Rule::with_payload(name, when.build()?, then)?)
}

fn input(json: &str) -> Result<Value> {
    Ok(read_value(
        &parse(json, &Limits::default())?,
        "",
        ValueContext::Data,
    )?)
}

fn checks() -> Vec<(&'static str, Build, &'static str, &'static str)> {
    vec![
        (
            "missing_email",
            field("customer").get("email").is_null(),
            "customer.email",
            "missing",
        ),
        (
            "bad_email",
            !field("customer")
                .get("email")
                .matches(r"^[^@\s]+@[^@\s]+\.[a-z]{2,}$"),
            "customer.email",
            "malformed",
        ),
        (
            "bad_quantity",
            field("quantity").le(0),
            "quantity",
            "not positive",
        ),
        (
            "total_mismatch",
            (field("quantity") * field("unit_price") - field("total"))
                .abs()
                .gt(0.01),
            "total",
            "does not match quantity x price",
        ),
        (
            "ships_before_order",
            field("ship_date").lt(field("order_date")),
            "ship_date",
            "before the order date",
        ),
    ]
}

fn validator(strict: bool) -> Result<RuleSet> {
    let rules = checks()
        .into_iter()
        .map(|(name, when, at, problem)| {
            rule(
                name,
                when,
                vec![("field", constant(at)), ("problem", constant(problem))],
            )
        })
        .collect::<Result<Vec<_>>>()?;
    let config = Config {
        hit_policy: HitPolicy::RuleOrder,
        strict,
        ..Config::default()
    };
    Ok(RuleSet::new(rules, config)?)
}

fn main() -> Result<()> {
    let order = input(
        r#"{"customer": {"name": "Ana"}, "quantity": "3", "unit_price": 19.99, "total": 59.97,
            "order_date": {"$date": "2026-10-30"}, "ship_date": {"$date": "2026-10-28"}}"#,
    )?;
    let lenient = validator(false)?;
    let decision = lenient.evaluate(&order)?;
    for entry in explain(&decision).rules {
        let reason = match (&entry.status, &entry.requirement) {
            (Status::Unknown, Requirement::Cause(cause)) => {
                cause.reason().map_or("", |r| r.code.as_str())
            }
            _ => "",
        };
        println!("{:<19} {:<10} {reason}", entry.rule, entry.status.as_str());
    }

    match validator(true)?.evaluate(&order) {
        Ok(_) => println!("strict: no error"),
        Err(error) => {
            let context = error.context();
            let rule = context.rule.as_deref().unwrap_or("-");
            let path = context
                .path
                .as_ref()
                .map(|p| to_string(&write_path(p)))
                .unwrap_or_default();
            println!("strict: {} in rule {rule} at {path}: {error}", error.code());
        }
    }
    Ok(())
}

const checks = [

import io.github.cleanrules.*;
import java.time.LocalDate;
import java.util.Map;

import static io.github.cleanrules.Conditions.*;

public class Orders {
    static Rule check(String name, Condition when, String field, String problem) {
        return Rule.named(name).when(when).then("field", field).then("problem", problem);
    }

    public static void main(String[] args) {
        var email = field("customer", "email");
        var validator = RuleSet.builder()
            .hitPolicy(HitPolicy.RULE_ORDER)
            .add(check("missing_email", email.isNull(), "customer.email", "missing"))
            .add(check("bad_email", email.matches("^[^@\\s]+@[^@\\s]+\\.[a-z]{2,}$").not(),
                "customer.email", "malformed"))
            .add(check("bad_quantity", field("quantity").le(0), "quantity", "not positive"))
            .add(check("total_mismatch",
                field("quantity").times(field("unit_price")).minus(field("total")).abs().gt(0.01),
                "total", "does not match quantity x price"))
            .add(check("ships_before_order", field("ship_date").lt(field("order_date")),
                "ship_date", "before the order date"))
            .build();

        var order = Map.of(
            "customer", Map.of("name", "Ana"),
            "quantity", "3",
            "unit_price", 19.99,
            "total", 59.97,
            "order_date", LocalDate.of(2026, 10, 30),
            "ship_date", LocalDate.of(2026, 10, 28));
        var decision = validator.evaluate(order);
        System.out.println(decision.fired());
        decision.outputs().forEach(System.out::println);
    }
}

package main

import (
	"fmt"
	"log"
	"time"

	cr "github.com/cleanrules/cleanrules/bindings/go"

func main() {
	check := func(name string, when cr.Expr, field, problem string) *cr.Rule {
		return cr.NewRule(name, when).Then("field", field).Then("problem", problem)
	}
	email := cr.Field("customer", "email")
	mismatch := cr.Field("quantity").Mul(cr.Field("unit_price")).Sub(cr.Field("total")).Abs()
	validator, err := cr.NewRuleSet([]*cr.Rule{
		check("missing_email", email.IsNull(), "customer.email", "missing"),
		check("bad_email", cr.Not(email.Matches(`^[^@\s]+@[^@\s]+\.[a-z]{2,}$`)),
			"customer.email", "malformed"),
		check("bad_quantity", cr.Field("quantity").Le(0), "quantity", "not positive"),
		check("total_mismatch", mismatch.Gt(0.01), "total", "does not match quantity x price"),
		check("ships_before_order", cr.Field("ship_date").Lt(cr.Field("order_date")),
			"ship_date", "before the order date"),
	}, cr.WithHitPolicy(cr.RuleOrder))
	if err != nil {
		log.Fatal(err)
	}

	order := map[string]any{
		"customer":   map[string]any{"name": "Ana"},
		"quantity":   "3",
		"unit_price": 19.99,
		"total":      59.97,
		"order_date": cr.NewDate(2026, time.October, 30),
		"ship_date":  cr.NewDate(2026, time.October, 28),
	}
	decision, err := validator.Evaluate(order)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(decision.Fired())
	for _, problem := range decision.Outputs() {
		fmt.Println(problem)
	}

/* A whole file, or NULL. */
static char *read_file(const char *path, size_t *len) {
    FILE *file = fopen(path, "rb");
    char *text = NULL;
    if (file != NULL && fseek(file, 0, SEEK_END) == 0) {
        long size = ftell(file);
        if (size >= 0 && fseek(file, 0, SEEK_SET) == 0 && (text = malloc((size_t)size + 1)) != NULL) {
            *len = fread(text, 1, (size_t)size, file);
        }
    }
    if (file != NULL) fclose(file);
    return text;
}

static int fail(cr_error *error) {
    fprintf(stderr, "%s: %s\n", cr_status_name(cr_error_code(error)), cr_error_message(error));
    cr_error_free(error);
    return 1;
}

int main(void) {
    /* The rule set document shown in the JSON tab. */
    size_t len = 0;
    char *text = read_file("orders.ruleset.json", &len);
    if (text == NULL) {
        perror("orders.ruleset.json");
        return 1;
    }
    cr_error *error = NULL;
    cr_ruleset *rules = NULL;
    cr_status status = cr_ruleset_read(text, len, CR_FORMAT_JSON, NULL, &rules, &error);
    free(text);
    if (status != CR_OK) return fail(error);

    const char *order =
        "{\"customer\": {\"name\": \"Ana\"}, \"quantity\": \"3\", "
        "\"unit_price\": 19.99, \"total\": 59.97, "
        "\"order_date\": {\"$date\": \"2026-10-30\"}, "
        "\"ship_date\": {\"$date\": \"2026-10-28\"}}";
    cr_decision *decision = NULL;
    char *outputs = NULL;
    if (cr_ruleset_evaluate(rules, order, strlen(order), NULL, &decision, &error) == CR_OK &&
        cr_decision_outputs(decision, &outputs, NULL, &error) == CR_OK) {
        puts(outputs);  /* a JSON array: one payload per selected rule */
    }
    cr_string_free(outputs);
    cr_decision_free(decision);
    cr_ruleset_free(rules);
    return error == NULL ? 0 : fail(error);
}

#include <cleanrules.hpp>
#include <iostream>

namespace cr = cleanrules;

int main() {
    auto validator = cr::ruleset::read(R"rules(
        HIT POLICY rule_order

        RULE missing_email
        IF customer.email IS NULL
        THEN field = "customer.email", problem = "missing"

        RULE bad_email
        IF NOT customer.email MATCHES "^[^@\\s]+@[^@\\s]+\\.[a-z]{2,}$"
        THEN field = "customer.email", problem = "malformed"

        RULE bad_quantity
        IF quantity <= 0
        THEN field = "quantity", problem = "not positive"

        RULE total_mismatch
        IF ABS(quantity * unit_price - total) > 0.01e0
        THEN field = "total", problem = "does not match quantity x price"

        RULE ships_before_order
        IF ship_date < order_date
        THEN field = "ship_date", problem = "before the order date"
    )rules", cr::format::text);

    auto order = cr::value::map({
        {"customer", cr::value::map({{"name", "Ana"}})},
        {"quantity", "3"},
        {"unit_price", 19.99},
        {"total", 59.97},
        {"order_date", cr::date{2026, 10, 30}},
        {"ship_date", cr::date{2026, 10, 28}},
    });
    auto decision = validator.evaluate(order);
    auto problems = decision.outputs();
    for (std::size_t i = 0; i < problems.size(); ++i) {
        std::cout << problems[i]["field"].as_string() << ": " << problems[i]["problem"].as_string()
                  << "\n";
    }
    std::cout << "\n" << decision.explain() << "\n";
}

The decision document records every rule's result tree, with each value read; its outputs are derived from it. It equals decision.to_dict() in Python.

The explanation

Why, and why not.

The explanation separates passed from could not tell. bad_email is unknown because there is no email to check; bad_quantity and total_mismatch are unknown because "3" is a string, a type mismatch between string and number. cleanrules does not coerce types, so a data-quality report built from this can list them as "not checked".

What happens if…

Change the input, see the outcome move.

Strict mode. When the shape of the data is your contract, unknowns should be errors. With strict=True, the first problem in rule order raises: here a missing email, even under is_null, because a missing key and an explicit None are different things. Send None for "no email" and the next error surfaces: the quantity's type. Each error names the rule, the field's path and the failing node.

Batches. evaluate_many evaluates a list of orders. Leniently, each order gets its decision; strictly, the first failing order raises, and row says which.

PythonPython binding · runs
from cleanrules import EvaluationError

strict = RuleSet(checks, hit_policy="rule_order", strict=True)
no_email = {**order, "customer": {"name": "Ana", "email": None}}
for data in (order, no_email):
    try:
        strict.evaluate(data)
    except EvaluationError as err:
        print(f"{type(err).__name__} | rule={err.rule} | path={err.path} | {err}")
